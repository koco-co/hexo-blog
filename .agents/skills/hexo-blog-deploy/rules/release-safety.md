# 发布安全规则

发布是外部副作用。本文件规定准备、授权、执行和验证的边界；机械判断以 `.agents/scripts/audit.mjs release` 为准。

## 1. 意图与授权

- “检查、准备、评估、生成发布清单”只授权只读预检和报告。
- 用户在当前请求中明确要求“执行部署”，且实时配置只解析出一个目标时，才可能包含实际发布授权。
- Skill 被显式调用只表示用户选择了工作流，不自动表示允许远程推送。
- 提交源码、清理工作树、修复配置、修改远程权限和部署是独立授权，不能相互推定。

## 2. 必须实时确认的事实

- 当前 Node.js 与已安装 Hexo 的最低版本；
- `package.json`、`_config.yml` 和 `_config.butterfly.yml` 可解析；
- 所有文章的发布级 Front Matter 与唯一 `abbrlink`；
- 项目根、`themes/butterfly-legacy/` 和 `.deploy_git/` 的独立 Git 边界；历史主题仅记录，不参与运行主题或发布阻塞判断；
- npm 运行主题、部署类型、脱敏后的远程目标和分支；
- 本地或 CI 路由的真实前置条件；
- 构建、预览、网络和远程认证能力。

不得把旧报告、调研快照或生成目录的文件时间当成当前事实。

## 3. 阻塞规则

以下情况默认阻止实际发布：

- 内容审计失败、`abbrlink` 缺失或重复；
- 本地 Node.js 不满足当前 Hexo；
- 项目根目录没有可验证的源码 Git 状态；
- 运行时 npm 主题缺失、未锁定或与配置不一致；
- Local 路由下 `.deploy_git/` 缺失、状态未知或不干净；
- 部署类型、远程仓库或分支不完整；
- 构建失败或本次改动要求的页面验收失败；
- 用户没有明确授权实际发布。

GitHub Actions 路由还必须满足：工作流发布到确认的独立成品仓库及 `main` 分支，发布目录为 `./public`，引用受限的 `PAGES_DEPLOY_KEY`，并包含 lint、审计测试、构建和 CI 发布预检。Secret 是否已在 GitHub 配置需要仓库管理员确认；CI 不可用不自动切换到本地部署。

## 4. 允许的命令边界

- 预检可运行只读审计、`git status`、版本查询和必要的构建/预览。
- 构建使用 `npm run build`；未经授权不运行 `npm run clean`。
- 本地实际部署只使用项目现有 `npm run deploy`，不手工操作 `.deploy_git/` 来绕过插件状态。
- CI 实际部署只执行用户授权的源码推送或既有工作流触发方式，不编辑工作流来临时放行。
- 不使用 `git reset --hard`、`git clean`、强制推送、递归删除或覆盖远程历史。

## 5. 凭据与报告

- 远程 URL 展示前移除用户名、密码、查询参数和片段。
- 不打印环境变量值、认证头、Token、API Key、Cookie 或 Secrets。
- 命令失败时只报告必要错误；若错误文本包含凭据，先脱敏。
- 报告明确区分“预检通过”“已执行部署”“线上已验证”；三者不能互相替代。

## 6. 回滚与停止

- 执行前说明可用的回滚依据；项目根没有 Git 时不得声称可完整回滚源码。
- 发布命令失败后保留状态，不自动重试、清理或改写远程历史。
- 线上验证失败时先判断缓存、构建、推送和页面行为层级；未经授权不再次部署。
- 任一阻塞项出现即在外部副作用前停止，并使用部署报告交接。
