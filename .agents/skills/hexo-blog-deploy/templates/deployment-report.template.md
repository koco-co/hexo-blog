# 部署报告

## 结论

- 状态：`ready`、`blocked`、`deployed` 或 `failed`
- 是否执行部署：`yes` 或 `no`
- 路由：`local` 或 `ci`

## 目标与授权

- 站点：填写脱敏后的公开站点 URL
- 远程：填写移除凭据和查询参数后的目标
- 分支：填写实时配置的分支
- 本次授权：说明用户明确允许的精确动作

## 预检

| 检查 | 结果 | 证据或阻塞原因 |
| --- | --- | --- |
| 运行时与依赖 | `pass`、`warning` 或 `blocked` | 命令与摘要 |
| 内容与 abbrlink | `pass`、`warning` 或 `blocked` | 审计结果 |
| 源码 Git 边界 | `pass`、`warning` 或 `blocked` | 状态摘要，不列敏感文件 |
| npm 运行主题 | `pass`、`warning` 或 `blocked` | 版本、锁定状态与有效来源 |
| 历史主题边界 | `pass`、`warning` 或 `blocked` | 仅记录状态，不作为 npm 主题阻塞依据 |
| 部署工作树 | `pass`、`warning` 或 `blocked` | 状态项数量 |
| 所选发布路由 | `pass`、`warning` 或 `blocked` | Local 目标，或 CI 成品仓库、分支、目录、质量门禁与 Secret 键名 |

## 构建与页面验证

- 构建命令及退出结果：填写实际执行证据
- 验证路由与视口：填写实际访问范围
- 浏览器与交互结果：填写真实观察结果

## 部署与线上验证

- 部署命令或工作流：填写实际执行动作；未执行时写“未执行”
- 远程结果：填写可验证状态
- 线上路由：填写实际访问页面
- 线上结果：填写已验证或未验证原因

## 状态分级

### 已验证

- 只列实际执行并有证据的项目。

### 未验证

- 列出因网络、权限、平台或范围未执行的项目。

### 阻塞

- 列出阻止部署或验收的具体问题及需要的下一步。

## 回滚与后续

- 可用回滚依据：填写真实存在的提交、制品或备份；不存在时明确说明
- 已发生的外部副作用：填写推送、部署或远程状态变化
- 下一步：只列当前范围内仍需用户决定或执行的事项
