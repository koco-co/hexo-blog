# 技术文风示例

本示例只展示解释的自然度、信息密度和辅助表达选择，不是文章模板，也不要求复用这些标题或同时使用代码、表格与类比。

## 正文片段

Python 调用函数时，不会把调用方的变量名直接交给形参。形参是在这次调用中创建的新名称，它与调用方的变量暂时指向同一个对象。接下来能否在函数外看到变化，取决于函数修改的是这个对象，还是只让形参改指向另一个对象。

```python
def update(items):
    items.append("new")  # 修改形参与调用方共同指向的列表
    print("函数内修改后:", items)


records = ["old"]
update(records)
print("函数外:", records)
```

两次输出都会包含 `"new"`。`append()` 没有让 `items` 指向新列表，而是修改了原列表，所以调用方通过 `records` 也能看到变化。

如果把函数改成下面这样，结果就不同了：

```python
def replace(items):
    items = []  # 只让局部名称 items 改指向新列表
    print("函数内重新绑定后:", items)


records = ["old"]
replace(records)
print("函数外:", records)  # 仍然是 ["old"]
```

| 函数内操作 | 改变了什么 | 调用方能否看到 |
| --- | --- | --- |
| `items.append("new")` | 原列表的内容 | 能 |
| `items = []` | 局部名称的指向 | 不能 |

可以把变量名暂时理解为贴在对象上的标签：函数调用时多贴了一张名为 `items` 的标签，撕下或移动这张局部标签不会改变调用方的标签。不过这个类比只解释“名称绑定”，并不完整描述引用计数、垃圾回收或不可变对象的实现。

## 闪卡解析片段

`items.append(x)` 修改的是形参与调用方共同指向的列表，因此调用结束后仍能通过调用方的变量看到新元素；`items = []` 只是把局部形参重新绑定到新列表，调用方的变量仍指向原列表。

```python
def compare(items):
    original = items
    items.append("visible")  # original 和调用方都能看到
    items = ["local"]        # 只有局部名称 items 改变
    return original, items
```

判断这类题时，不要背“Python 是传值还是传引用”这一句术语。先问函数操作的是共享对象，还是局部名称：原地修改共享对象会向外可见，重新绑定形参不会。这个判断也解释了为什么可变默认参数、闭包和容器副作用都需要同时区分“对象”和“名称”。
