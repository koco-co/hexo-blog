# 站点定制工作流

本工作流处理 Hexo/Butterfly 配置、自定义 CSS/JavaScript、数据页和已有站点功能。开始前完整读取 `rules/project-contract.md` 与 `references/project-map.md`。

## Phase 1：定位真正的所有权

1. 从用户目标反推当前实现，搜索 `_config.yml`、`_config.butterfly.yml`、`source/css/`、`source/js/`、页面文件和主题渲染代码。
2. 运行 `node .agents/scripts/audit.mjs project --json`，记录运行时、注入资源、敏感字段位置和三个 Git 边界。
3. 判断变更应落在配置、主题覆盖、自定义脚本、数据还是页面内容。
4. 如果只有修改 `themes/butterfly/` 才能实现，先展示将受影响的主题文件、当前独立 Git 状态、升级冲突和覆盖层替代方案，等待明确授权。

完成信号：已找到最窄的稳定修改点，没有把主题上游代码当作默认编辑区。

## Phase 2：按分支实施

### Hexo 主配置

- 只修改 `_config.yml` 中与目标直接相关的键。
- 改永久链接、URL、目录、渲染或部署配置前，说明兼容影响；部署配置的实际使用仍归部署 Skill。
- 不把部署远程、加密信息或第三方凭据复制到说明文档。

### Butterfly 配置

- 修改根 `_config.butterfly.yml`，不修改主题目录内的默认配置。
- 保持两空格缩进、布尔值 `true`/`false` 和现有中文注释风格。
- 调整菜单、搜索、评论、侧栏或资源注入时，核对相关页面、插件和本地资源是否存在。

### CSS

- 全站覆盖优先使用 `source/css/custom.css`；归档/分类/标签、文章标签或宇宙背景使用已有专属样式文件。
- 选择器范围尽量靠近目标组件，验证暗色模式、移动端、长文本和交互状态。
- 不复制主题整段 Stylus 作为覆盖；只覆盖必要声明并注明目的。

### JavaScript

- 使用 ES6+ 和局部作用域；不得新增无必要的全局变量。
- 初始化函数必须幂等。重复触发 `pjax:complete` 时不能重复绑定监听器、重复插入 DOM 或累积定时器。
- 目标 DOM 不存在、第三方 API 失败或响应异常时安全降级，不影响正文阅读。
- 第三方网络调用明确超时、隐私和失败状态；凭据只从既有安全位置读取。

### 页面和数据

- 保留页面 `type` 与主题模板的对应关系。
- 修改友链、照片、视频、音乐等数据前读取完整现有结构，不把展示 HTML 与数据字段混用。

完成信号：所有修改位于正确所有权层，功能初始化、降级和资源引用闭合。

## Phase 3：同步资源注入

1. 新增全站 CSS/JavaScript 时，确认它确实需要全站加载；否则在目标页面按需加载。
2. 需要 `inject` 时只加入对应本地路径，避免重复加载同一资源。
3. 删除或重命名资源时同步更新注入项；运行项目审计确认没有 `INJECTED_ASSET_MISSING`。
4. PJAX 环境下验证首次加载和站内跳转后的状态都正确。

完成信号：注入资源存在、只加载一次，并在目标生命周期工作。

## Phase 4：交接验证

1. 对修改的 JavaScript 运行 `node --check <文件>`；对 YAML 运行项目审计。
2. 完整执行 `workflows/§03-verification.md`。
3. 使用 `checklists/maintenance-acceptance.md` 检查视觉、交互、响应式、控制台和失败降级。

失败路径：主题授权缺失、配置解析失败、资源悬空、控制台异常、PJAX 重复执行或视觉不一致时停止交付，修复后重新验证。
