# 本地图片工作流

本工作流处理正文图片、文章封面、照片墙资源及旧图床迁移。开始前完整读取 `rules/project-contract.md`、`references/project-map.md` 和目标 Markdown；涉及标签参数时同时读取 `workflows/§04-tag-plugins-plus.md` 与对应标签参考。

## Phase 1：确认真实使用范围

1. 扫描 `source/**/*.md` 的 Front Matter、Markdown/HTML 图片和标签外挂图片参数。
2. 区分真实渲染内容与围栏代码、普通教程文本；只迁移博客实际使用的图片，不按旧图床仓库全量复制。
3. 运行 `node .agents/scripts/audit.mjs assets --json`，记录真实旧图床引用、教程示例和本地图片引用数量。
4. 外部第三方头像、徽章、厂商文档图片或 API 资源不因本地迁移自动纳入范围。

完成信号：每个目标资源都能追溯到真实渲染引用，非目标和教程示例已明确。

## Phase 2：迁移与命名

1. 旧图床迁移固定来源仓库和提交，先在临时目录取回目标文件并校验路径，不直接在项目中试错下载。
2. 迁移目标为 `source/img/picgo-images/`；写入前检查同名文件和内容碰撞。
3. 保持原始字节，不自动压缩、缩放、裁剪或转换格式。扩展名缺失但文件类型可确认时补正确扩展名；百分号编码文件名解码为可读名称，并清理意外空格。
4. 在 `tools/hexo-blog/image-migration-map.json` 记录来源仓库、固定提交、源路径、目标路径、字节数、媒体类型和 SHA-256。
5. 新图片不需要追加到历史迁移清单，但必须使用有意义、无凭据且不冲突的文件名。

完成信号：目标文件唯一、可读，迁移清单完整，字节和哈希与固定来源一致。

## Phase 3：改写引用

1. 真实渲染引用统一改为 `/img/picgo-images/<文件名>`。
2. 保留 Front Matter 其他字段、Markdown 替代文本、链接目标、标签名称、参数顺序、分隔符和容器闭合。
3. 围栏代码和普通教程说明中的旧图床地址默认保持不变；除非用户另行要求更新教程叙事。
4. 不把 PicGo Token、上传器配置或任何凭据复制到仓库、迁移清单、日志或报告。

完成信号：只有已确认的真实引用被替换，教程和第三方资源没有被机械改写。

## Phase 4：后续本地优先

1. 新图片直接保存到 `source/img/picgo-images/`，文章先引用本地路径，不再执行远程上传。
2. 图片优化是独立任务；未获确认时保持原始质量和格式。
3. 移除 PicGo 旧上传配置、删除或归档旧图床仓库属于外部状态变更，必须在本地迁移、构建和页面验证全部通过后，按用户明确授权单独执行。
4. 旧仓库需要保留回退能力时优先归档只读，不删除；无法确认登录态或权限时报告阻塞。

完成信号：日常写作不依赖外部图床，远程处置没有越过授权和验证门禁。

### AI 故事插图与分镜

1. 在文章预案中先确定图片解释的情境、选择或后果，以及插入位置、角色对应、替代文本和不靠图片也能读懂的叙述。精确时序、数量、公式和代码优先用可核对的图表；真实界面和报错使用真实截图。
2. 用户确认含图片的预案后，读取当前环境可用的图像生成 Skill 与工具要求，按确认范围生成；不把某台机器的工具名或缓存路径写死进文章。工具不可用或结果不合格时报告并提交替代预案，不留悬空引用、不把占位图当成完成结果。
3. 提示词说明教学目的、情境与动作、跨分镜一致性、构图和禁止误画的关系；故事后段才揭示的答案不提前印在图片上。准确术语、关键数字和技术结论保留为正文文本，避免只依赖生成图里的文字。
4. 逐张目视检查动作、顺序和映射、文字可读性及多余角色、错误符号或误导性的截图外观。修复后才保存到 `source/img/picgo-images/`；新生成图片不加入历史迁移清单，不覆盖系列封面。
5. 正文明确图片属于情境示意而非实验或历史证据；未经授权不将私人资料发送给外部生成服务。格式、压缩与裁剪继续遵守本工作流的授权边界。

完成信号：图片承担具体教学任务，角色与机制对应准确，本地文件和引用存在，生成状态与未验证项如实记录。

## Phase 5：验证

1. 运行 `node .agents/scripts/audit.mjs assets --json`，要求迁移文件大小与 SHA-256 全部通过、真实旧图床引用为零、本地图片引用无缺失。
2. 运行 `content`、`tags` 和审计工具测试；按 `workflows/§03-verification.md` 在隔离目录完成真实 Hexo 生成。
3. 在桌面和移动视口打开所有受影响路由，检查图片完成加载、自然尺寸有效、无 404，并查看控制台和网络错误。
4. 本地构建与页面检查不能证明 GitHub Actions、远程部署或线上页面成功；未授权时不执行清理或部署。

失败路径：来源路径不明、哈希不符、目标碰撞、真实旧图床引用残留、本地图片缺失、构建失败或页面 404 时停止远程处置，修复后重跑受影响检查。
