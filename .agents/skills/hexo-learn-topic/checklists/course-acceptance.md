# Hexo 课程验收清单

## 路线与文章地图

- [ ] 主题、版本或 Commit、零基础基线、前置、范围和毕业成果有当前来源。
- [ ] 第一次确认前的回复使用学习大纲消息模板，开头已说明“这是什么、重点看什么、现在做什么”，正文只包含学习目标、所需主题、Hexo 文章安排以及图解、实验和闪卡分配，结尾只有一项学习范围与顺序确认；调研来源、能力账本、Reviewer 过程、验证命令和文件操作没有混入回复。
- [ ] 第一轮的 `N` 个学习主题名称简短且可直接作为标题，并逐项、同名且仅一次映射到 `N` 篇主题文章；系列总数为 `N+1～3`，没有在第二轮擅自拆分、合并、改名、遗漏或新增主题文章。
- [ ] 路线经过第一次确认，文章地图经过干净上下文 Curriculum Reviewer 与第二次确认。
- [ ] 前四类正文处置各有唯一主文章；明确不纳入项没有文章或章节但有来源和理由。文章依赖无环；课程编号、篇内章节、示例步骤和练习均按知识依赖顺序排列。
- [ ] 当前版本的官方能力全集有入口 manifest、遍历边界、稳定标识和来源；官方集合与账本集合完全相等，官方仅有、账本仅有、重复和未处置均为 0。
- [ ] `data/<主题路径段>.json` 使用 schema v2，能仅凭项目文件无损恢复第一轮主题、可选篇、文章清单及每项对象或主题、来源、版本状态、强制镜像、处置、主文章、目标章节、理由和验证状态；字段级往返比较完全相等。
- [ ] Curriculum Reviewer 已从官方索引独立执行全量差集；没有用抽样、已有文章目录或作者提供的账本代替全集复算。
- [ ] 调用模型不同的同步/异步 API 使用不同稳定标识；合并条目的强制镜像逐项对账。旧接口补充集有替代项、主文章、章节、来源和正文证据。
- [ ] 第一轮学习主题本身采用宽维度，没有单个 API 对应一个学习主题；低频能力只在已确认且最多一篇的可选进阶路线汇总。
- [ ] 旧文复用有质量与版本依据；升级或新建建议没有未经确认实施。

## 课程脚手架

- [ ] 文件只位于 `source/_posts/learn-topic/<主题路径段>/` 的确认范围。
- [ ] 路线图与占位文章创建后的回复使用“学习路线图已创建”消息模板，只说明课程、学习顺序、辅助内容和下一篇文章；目录树、文件路径、Front Matter、命令、审计、Reviewer 和验证状态没有混入回复。
- [ ] 主题路径段、路线图名和文章名均为安全的单个名称；每个规范化目标的父目录严格等于课程目录。
- [ ] 文件名、标题使用 `主题(序号)主题` 系列格式，第一篇为 `主题(一)入门路线`，可选进阶篇为 `主题(序号)进阶路线`；可选结尾篇最多一篇，并按课程性质使用 `综合实战`、`项目实战` 或 `知识总结`；description 为单行普通 YAML 字符串。
- [ ] 第二次确认后、占位写入前完成系列封面生成；项目最终只保留 `source/img/picgo-images/<主题路径段>-course-cover.png` 这一张 `1920 × 1080` PNG，修复验收问题时允许重试候选，全系列 `cover` 完全一致。
- [ ] 封面使用 `assets/course-cover-reference.png` 作为风格与构图参考，形成“顶部 4～5 个课程关键词、中央准确主题标识、底部唯一大标题”的层级；参考图中的 Python 内容和水印没有泄漏到其它主题。
- [ ] 封面使用深蓝黑工业科技背景和克制的青蓝、紫色及主题强调色霓虹；大标题与顶部关键词逐字准确且各出现一次，中央 70% 安全区经缩略图和移动裁切检查后仍能识别课程主题。
- [ ] 封面没有随机风景、无关人物、动漫主体、长副标题、未冻结文字、乱码、水印、错误 Logo、畸形图标、空旷单主体或廉价通用科技横幅；生成失败时没有回退到 Butterfly 随机封面。
- [ ] 每篇 `series_order` 是与中文序号一致的非重复正整数；正文使用 `{% course_series %}`，没有依赖标题或发布日期排序。
- [ ] 路线图可渲染且为公开状态，其他占位文章均有占位标记并为 `published: false`。
- [ ] Skill 数据契约持久化入口 manifest、完整全集、逐项账本和集合摘要；新会话只凭项目文件可以恢复，所有课程 Front Matter 均不含 `learn_topic_capability_ledger`。
- [ ] 每个占位包含完整 Front Matter、职责、大纲、示例、视觉、FAQ、自测和来源计划。
- [ ] 完整文件先在隔离目录通过审计；真实目录先写入并读回未发布文章，路线图最后写入，没有默认公开中间态。
- [ ] 内容审计递归覆盖全部课程文章，没有路径冲突或遗漏。

## 单篇正文

- [ ] 当前只写一篇；批量模式也按知识依赖逐篇处理，动态事实已刷新，视觉预案已由用户确认。
- [ ] 正文包含机制、完整示例、验证、失败边界、踩坑、FAQ、自测和来源。
- [ ] 关系、流程、状态、层级和比较优先使用合适视觉，正文没有连续长段堆积。
- [ ] Mermaid 流程图方向与内容密度匹配：只有不超过 4 个主链节点、无复杂分支或子图且标签较短时使用 `LR`；其他情况使用 `TD/TB`，桌面与移动端均无文字压缩或横向溢出。
- [ ] Mermaid 全部使用 `{% mermaid %}` 容器，不存在 Markdown Mermaid 围栏；公开文章的 `常见问题` 至少包含一张 `flashcard` 或 `flashcard_ref`。
- [ ] 四类隐藏标签按教学目的使用，核心结论、命令和风险直接可见。
- [ ] 每张 `flashcard` 有唯一稳定 ID、单一卡组、`priority:1|2|3`、精简回答和详细解析；跨文章复用只用 `flashcard_ref`。
- [ ] Article Reviewer 无阻塞项；修复后已完成独立复查。
- [ ] Article Reviewer 一次只审一篇，输入包含官方能力全集、覆盖处置账本和该篇分配，并逐项输出 Capability Reconciliation。
- [ ] 该篇所有 `核心详解`、`正文简述`、`进阶路线` 与 `弃用迁移` 条目均有正文证据；常见旧接口没有因弃用而无声消失。
- [ ] H2/H3 简洁且按知识顺序组织；倒数第二个 H2 是 `常见问题`，最后一个 H2 是 `参考资料`。
- [ ] 参考资料使用 `linkgroup` 与 `link` 资料卡片；超过 6 项时按实际用途简短分组，顺序与图标降级符合 `rules/learning-article-quality.md`。
- [ ] 公开文章没有“来源”“来源与核验范围”或“核验于 YYYY-MM-DD”等内部工作文案。

## 验证与状态

- [ ] `node .agents/skills/hexo-learn-topic/scripts/audit.mjs lint --json` 返回 `status: pass`；项目、目录与命名、配置与依赖、代码语法、Skill 与软链接、文档链接、所有文章与页面、课程契约、标签和图片资源均无错误。
- [ ] lint 出现任一具体文件错误时已经修复并重跑；没有在 lint 非 `pass` 时交给用户验收。
- [ ] `hexo-blog-maintenance` 完整负责初稿及 Reviewer 修订后的审计、隔离 `--draft` 生成与浏览器验收。
- [ ] 目标路由完成桌面、移动端、明暗主题、展开交互、控制台和资源检查。
- [ ] 课程导航按知识顺序展示，当前篇、进度、键盘焦点和长标题状态清楚，桌面双列与移动单列均无溢出。
- [ ] 公开候选先在隔离副本完成普通生成、发布级审计和公开路由检查，才同步真实 `published: true` 及路线图目标行。
- [ ] 提升公开状态时已自动删除占位标记，没有把完整正文留在 `published: false` 等待用户提醒。
- [ ] 路线图中目标文章的状态、链接形态与前置关系作为整体更新并读回；失败时恢复为无链接的阻塞状态。
- [ ] 真实项目最终失败时已恢复未发布源码并用普通构建覆盖公开生成物；恢复失败时明确阻塞部署且未擅自清理。
- [ ] 路线图状态、文章 Front Matter 与实际证据一致；未验证和阻塞项单独说明。
