# 学习文章质量规则

## 1. 内容主线

每篇从真实问题、场景或贯穿案例开始，先建立读者要解决的任务，再解释心智模型、机制、完整示例、失败边界和验证。定义只在解决问题时出现，不连续堆砌术语。

篇内知识按“前置概念 → 基础操作 → 组合应用 → 失败边界 → 结果验证”推进。

### 章节层级

- 开头先用一个有语义的标签块说明贯穿问题、观察任务和成功证据，不另建泛化的“学习目标”；
- H2 承担完整读者任务，例如建立模型、完成配置、运行实验或判断失败；H3 只拆同一任务的子步骤、对象或分支；
- 同一层级连续出现 API 名、命令名或配置键时，先按读者任务归组，不用扁平目录代替教学结构；
- 一个概念先建立可见摘要和心智模型，再展开字段、方法和边界；不能先给大段参考表再补解释；
- 完整配置、长日志、完整脚手架和次要案例进入合适的折叠标签，正文主线保留最小完整示例、关键差异和验证；
- FAQ 只收真实问题，不能和“失败边界”“踩坑”重复讲同一件事；能够在正文直接消除的误解优先在正文处理。

常见组织顺序是“问题定位 → 心智模型 → 核心机制 → 最小实验 → 组合应用 → 失败边界 → 结果验证 → 复习”，但文章角色和知识依赖可以合并相邻环节。不得为了套模板制造空章节。

### 标题与文案

- H2/H3 只承担导航：使用简短的对象、动作或边界名，通常不超过 15 个字符；技术标识可以保留原名，但不在标题中追加解释性副标题。
- 不用“为什么……”“如何……”“是否……”等聊天式问句作为普通章节标题；真实问题放到正文中的问题引导或 `常见问题` 闪卡。
- 不用冒号、顿号、斜杠连续拼接多个知识点。需要比较多个维度时，标题保留主题，详细维度放在首段、表格、Mermaid 或 `tabs` 中。
- 标题旁的文案直接说明读者要完成的动作、判断证据和失败边界，不写“本文将”“如下所示”“为了方便大家”等过程话术，不把调研、审计或生成过程写进公开正文。
- `常见问题`、`参考资料` 是固定 H2；FAQ 问句和资料分组可以保留问题/资料名称，但仍要避免无关背景和内部工作文案。
- 已发布文章不保留 `章节计划`、`学习目标` 或 `验证方式` 这类内部合同；路线图负责课程顺序，正文负责知识解释。公开正文的块级标签和导航文案以 `rules/published-article-contract.md` 为唯一规范源。

课程篇序使用 Front Matter 的 `series_order` 作为唯一稳定顺序，数值必须与文件名和标题中的中文序号一致。正文使用 `{% course_series %}` 渲染课程导航，不用标题字符顺序或发布日期代替知识顺序。

代码示例必须完整到能理解输入、关键步骤、输出和错误表现；能够运行时使用当前环境或隔离环境验证，不能运行时明确标记未验证。

正文必须实现覆盖处置账本分配给该篇的全部条目。`核心详解` 需要机制、完整示例、失败边界和验证；`正文简述` 需要用途与选择边界；`进阶路线` 需要在对应对象或能力组的索引中准确列名，并说明该组的学习边界和进入条件，不要求把每个低频成员扩写成独立正文；`弃用迁移` 需要指出当前替代项及旧代码迁移方式。不能因为推荐新接口就让常见旧接口从课程中无声消失。

文章无需罗列与读者任务无关的全部方法，但任何省略都必须先在课程账本中被明确处置；作者不能在写作阶段自行缩小已经确认的分配范围。

## 2. 可视化优先

以下内容优先使用视觉表达：三个及以上节点的关系、连续步骤、状态变化、层级、调用链、布局和多字段精确比较。

- 架构、流程、状态和依赖优先 Mermaid，并且必须使用 Butterfly `{% mermaid %}` / `{% endmermaid %}` 容器，不使用 Markdown Mermaid 代码围栏；
- 精确比较优先表格，真实数据趋势才使用 Chart.js；
- UI、操作和错误状态使用真实截图；
- 位图只在代码图表或截图不能准确表达时创建，并保存到项目规定的本地图片目录；
- 普通 Markdown 负责标题、代码、表格、列表和结构连接；连续解释必须按 `rules/published-article-contract.md` 落在块级标签中，不允许整篇文章形成裸 Markdown 文本墙，也不允许一段文字同时承担多个读者任务。
- 标签选型完整遵循 `rules/article-tag-selection.md`。先确定读者任务，再从当前完整注册目录选择标签；`note` 不是普通段落容器，`folding` 与隐藏标签不能遮蔽主线，`tabs` 只承载真正平行的方案。

Mermaid 流程图按内容密度选择方向：主链不超过 4 个节点、没有复杂分支或子图、标签较短，并且桌面与移动端均不拥挤时可以使用 `LR`；节点更多、存在分支或子图、标签较长，或横向渲染会压缩文字和产生溢出时使用 `TD` 或 `TB`。最终以真实页面可读性为准；`LR` 出现缩小、拥挤、横向滚动或超出正文宽度时改为 `TD/TB`。

不设置标签或图片数量指标，但每篇公开课程文章必须通过逐块标签覆盖检查。视觉组件必须减少理解成本，不能装饰空内容；只有课程导航、资料链接或 `course_series` 不算正文视觉组合。

重复组件与标签多样性的复查统一执行 `rules/article-tag-selection.md`，不在公开正文解释审计过程。

## 3. 文章角色与主动回忆

文章先按角色决定内容，不按“每篇必须凑齐章节”套模板：

- `入门路线`：只回答学什么、先学什么、需要什么前置和如何开始；固定 H2 为 `课程目标`、`前置条件`、`学习路径`、`文章安排`、`开始学习`、`参考资料`。它可以有 Mermaid 和主题边界提示，但不放 FAQ、flashcard 或课程生产过程。
- 主题文章：围绕一个已确认学习主题完成机制、示例、失败边界和验证；只有存在真实且可复习的问题时才增加 `常见问题` 与闪卡。
- `进阶路线`：只收录主线之外的专项扩展、迁移或进入条件；卡片必须是专项概念，不得写“从哪篇开始”之类导航题。
- `综合实战`/`项目实战`/`知识总结`：以任务、证据和复盘为主；仅把会长期复用的设计取舍或故障判断做成卡片。

FAQ 候选优先来自官方文档、GitHub Issues/Discussions、Stack Overflow 和其他可核验社区问题；招聘网站只用于发现面试关注点，技术答案回到一手资料。没有真实问题时删除 FAQ，而不是为了形式保留空章节。

- `flashcard`：需要进入长期复习队列的 FAQ、面试题或自测；每题必须有稳定且唯一的 `id`、单一卡组、`priority:1|2|3`，并同时提供精简回答和详细解析。`priority` 是 `hexo-flashcard-plugin` 的必填字段，不得省略或写成其他值；
- `flashcard_ref`：跨文章复用已有闪卡时只引用其稳定 `id`，不得复制题目、回答或解析；同一道题只保留一个原始定义；
- `folding`：概念深入解释、补充说明、长代码、日志或其他不进入复习队列的折叠内容；折叠前直接展示本块摘要和阅读理由；
- `hideToggle`：只在原文阅读、不进入复习队列的章节末完整自测；
- `hideBlock`：先推演再揭晓解析；
- `hideInline`：术语、命令、参数或短答案。

核心结论、必要命令、安全风险和故障恢复步骤保持直接可见。隐藏内容中不使用 H1-H6 标题。

## 4. 可读性

段落围绕一个动作或判断展开；主题改变时使用小标题、列表、表格、代码或图示重新组织。避免连续的长段正文，也避免把每句话拆成碎片。

总结、适用边界和证据判断放在复习内容之前；不要在公开正文重复课程导航或内部合同。入门路线严格按六个固定 H2；其他公开主题、进阶和实战文章如有 `常见问题`，其内容必须至少使用一张 `flashcard` 或 `flashcard_ref`，否则删除该章节；这些文章最后一个 H2 固定为 `参考资料`。公开正文不出现“来源”“来源与核验范围”或“核验于 YYYY-MM-DD”等内部调研文案。

## 5. 参考资料编排

`参考资料` 只收录正文实际使用或能帮助读者继续学习的最终公开地址。链接名称简短且能区分内容，不附加核验日期、来源说明或内部工作备注。

- 使用 `{% linkgroup %}` 包裹 `{% link 标题, URL, 图标 %}`，由博客统一渲染为桌面双列、移动单列的资料卡片；不使用普通项目符号列表或按钮堆叠代替；
- 每张卡片保留资料名称、完整目标 URL 和显式的官方图标。图标优先使用目标资料同域或同组织的 favicon/logo，并在写入前验证返回成功且内容类型为图片；不得省略第三个参数，也不得使用默认 avatar、cover、placeholder、课程封面、文章预览图、资料页本身或无关域名图片代替来源图标。官方产品 CDN 只有在能明确证明属于目标资料（例如 Chrome 官方文档使用 Google 官方 Chrome logo）时才可作为例外。lint 会检查图像 URL 的扩展/路径、域名关系、允许的官方 CDN 例外和本地文件签名，并报告具体行号；卡片的文字标题和 URL 必须在图片失效时仍可读；
- 资料不超过 6 项时直接使用一个卡片组；超过 6 项时按“官方文档”“扩展工具”“标准规范”等实际用途使用简短 H3 分组，每组分别闭合 `linkgroup`；
- 分组和卡片顺序遵循正文知识依赖与使用顺序，不按字母、发布时间或随机顺序排列；
- 外部图标失效时，资料名称与 URL 仍必须可读，不能让图片承担唯一识别信息；无法确认域名图标时先使用通用链接图标并记录待核实项，不猜测图片地址。
