# 已发布课程文章合同

本文件是系统课程公开正文的唯一内容与视觉规范。`SKILL.md`、维护工作流、文章模板、Reviewer 和 `audit.mjs` 只引用本合同，不各自发明同名规则。

课程契约的 `course.public_article_contract` 使用 `v1` 激活本合同的公开正文门禁。新建或整体重写的课程必须写入该字段；未带该字段的既有课程属于待迁移内容，不得作为新课程脚手架或新文章的默认模式。

## 1. 读者内容与内部资料分离

课程契约、能力 ID、处置账本、Reviewer 结论、写作门禁和文章依赖属于 `.agents/skills/hexo-learn-topic/data/`、文章地图或路线图，不属于公开文章正文。

`{% course_series %}` 是课程进度和文章入口的唯一导航。公开正文不得再次列出“前置文章是……”“上一/下一篇……”“从第几篇开始”“本文分配能力为……”或类似导航、进度和账本信息。正文只解释读者需要掌握的知识关系；路线图负责展示课程顺序和状态。

公开正文也不得暴露内部能力编号或文章编号，例如 `MOD-001`、`CN-TR-005`、`文章(七)`；闪卡标签中的稳定 ID 和 `flashcard_ref` 的引用 ID 属于渲染元数据，可以保留，但不得在普通说明、表格或段落中解释这些编号。

已发布课程文章不得出现下列内部合同标题：

- `学习目标`、`章节计划`、`验证方式`；
- `文章职责`、`内容计划`、`正文大纲`、`文章地图`；
- `视觉与闪卡设计`、`公开候选门禁`、`课程生产`、`统一封面与文章收尾`。

入门路线只使用项目固定的六个 H2：`课程目标`、`前置条件`、`学习路径`、`文章安排`、`开始学习`、`参考资料`。其他公开课程文章用一段带标签的“本节要解决”定位正文进入主题，不另起一组泛化学习目标。

## 2. 标题和正文的渲染分工

H2/H3 必须保留为普通 Markdown 标题，因为它们承担目录、锚点、键盘导航和屏幕阅读器层级；不把 `{% label %}` 或其他行内标签塞进标题来伪造目录。标题只写简短的对象、动作或边界，原因、条件、步骤和失败边界放在标题下的标签块、表格、图示或代码中。

每个有意义的解释块都必须先选择渲染角色，再写入正文：

| 读者任务 | 首选标签 | 公开信息要求 |
| --- | --- | --- |
| 定位、结论、风险和边界 | Butterfly `note`，或插件 `tip` | 结论直接可见，不能只藏在折叠里 |
| 方案、平台、协议或代码切换 | Butterfly `tabs` | 每个选项必须有适用条件和差异 |
| 关系、流程、状态和时序 | Butterfly `mermaid`、`timeline`、`chartjs` | 图下必须有文字结论或验证边界 |
| 非关键补充、日志和长配置 | `folding`、`hideToggle`、`hideBlock` | 核心结论不得只放在隐藏区 |
| 长期复习的问题 | `flashcard`、`flashcard_ref` | 题目必须是真实问题，ID 全站唯一 |
| 官方扩展阅读 | `linkgroup`、`link` | 标题和 URL 在图片失败时仍可读 |

“解释块”是一个围绕同一判断或动作的连续正文段落组。位于标签容器内的正文算已承载；代码围栏、表格、列表、标题、标签自身和必要的空行是结构例外。单独在段落里插入一个行内 `emp`、`bubble` 或 `label` 不算承载；必须用块级标签包住该解释块。没有任何结构需要时，不为了通过检查硬塞标签，而应把内容改成表格、列表、代码或删除无价值文案。

## 3. 每篇文章的内容闭环

主题、进阶和实战文章按以下顺序组织真实内容，具体标题可按主题命名：

1. 先用一个标签块说明贯穿问题或观察任务；
2. 先解释心智模型，再解释字段、状态或调用链；
3. 用 Mermaid、表格、时序图或可复现实验承载复杂关系；
4. 直接说明失败边界、误区和证据判断；
5. 只有存在长期复习价值时才增加复习卡片和 `常见问题`；
6. 最后一个 H2 固定为 `参考资料`，只放真实使用过的官方资料卡片。

每个 H2/H3 必须有唯一读者任务。只有目录、概念堆砌、空泛总结或“一句验证方式”而没有可观察证据的章节不得发布。

## 4. 公开前硬门禁

- `audit.mjs content --release` 必须报告没有公开内部标题、导航/账本文案和标签外裸解释块；
- 标签必须来自当前注册能力，容器按栈顺序闭合，Mermaid 只能使用 Butterfly 容器；
- `常见问题` 中的每个长期复习问题必须使用 `flashcard` 或 `flashcard_ref`，没有真实问题就删除整个章节；
- 机械审计通过后仍要完成真实 Hexo 构建、目标路由的桌面/移动和明暗主题检查；静态通过不等于内容或视觉通过。
