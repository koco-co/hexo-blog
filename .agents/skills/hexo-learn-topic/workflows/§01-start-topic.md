# 从知识点开始课程

本工作流处理技术、框架、语言、工具或单独知识点。开始前完整读取 `rules/research-policy.md` 与 `rules/curriculum-quality.md`。

## Phase 1：确定研究对象

1. 从用户输入和当前环境识别主题、预期用途与已指定版本。
2. 用户没有说明学习基础时采用零基础教学基线；这不覆盖已经查明的用户环境事实。
3. 只有目标版本、最终用途或语言绑定存在多个合理答案且会改变路线时，才一次询问一个决策。

完成信号：主题边界和可观察的课程成果明确。

## Phase 2：核验当前资料

1. 查找官方文档入口、受维护版本、发布记录、语言或运行时要求。
2. 按 `rules/research-policy.md` 建立官方能力全集，记录稳定标识、对象或主题、版本状态、来源和总数。
3. 梳理硬前置、可随课补齐知识和拓展知识。
4. 搜索官方示例、源码、GitHub Issues/Discussions 与高质量技术问答，记录高频误区和失败场景。
5. 对版本敏感、争议或安全相关结论至少使用一手资料核验。

完成信号：来源清单包含访问日期、版本适用性和事实用途；官方能力全集可复算且缺口已明确。

## Phase 3：形成路线提案

1. 按 `templates/roadmap-proposal.template.md` 形成路线、阶段、依赖、范围、毕业成果和学习主题。学习主题必须是足够宽、可直接成为文章标题的名称，不得把将在第二轮继续拆分的主题组放入第一轮。
2. 按 `rules/curriculum-quality.md` 把 `N` 个学习主题逐项映射为 `N` 篇同名主题文章，再加入必选入门路线和确有必要的可选进阶路线、实战或总结；总数只能是 `N+1～3`。
3. 输出前完整读取 `templates/learning-outline-reply.template.md` 与 `examples/learning-outline-reply.example.md`，把内部路线提案转换为用户可识别的“学习大纲”回复；先说明这是什么、重点看什么和现在做什么，再展示学习目标、所需主题、逐项对应的 Hexo 文章安排以及图解、实验和闪卡分配。调研来源、能力账本、Reviewer 过程、验证命令和文件操作不得进入学习大纲回复。
4. 不在本阶段创建文章、目录或持久状态。
5. 按回复模板展示完整学习大纲并等待第一次确认；结尾只保留“学习内容和顺序是否符合目标”这一项确认，用户调整后重新展示受影响内容。
6. 确认后冻结学习主题、主题顺序、文章映射与可选加篇，转入 `workflows/§03-design-course.md`。

失败路径：关键官方资料不可访问、主题边界无法确认或版本事实相互冲突时停止，不用推断补齐路线。
