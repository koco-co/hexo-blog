# 从知识点开始课程

本工作流处理技术、框架、语言、工具或单独知识点。开始前完整读取 `rules/research-policy.md` 与 `rules/curriculum-quality.md`。

## Phase 1：确定研究对象

1. 从用户输入和当前环境识别主题、预期用途与已指定版本。
2. 用户没有说明学习基础时采用零基础教学基线；这不覆盖已经查明的用户环境事实。
3. 只有目标版本、最终用途或语言绑定存在多个合理答案且会改变路线时，才一次询问一个决策。

完成信号：主题边界和可观察的课程成果明确。

## Phase 2：核验当前资料

1. 查找官方文档入口、受维护版本、发布记录、语言或运行时要求。
2. 梳理硬前置、可随课补齐知识和拓展知识。
3. 搜索官方示例、源码、GitHub Issues/Discussions 与高质量技术问答，记录高频误区和失败场景。
4. 对版本敏感、争议或安全相关结论至少使用一手资料核验。

完成信号：来源清单包含访问日期、版本适用性和事实用途；缺口已明确。

## Phase 3：形成路线提案

1. 按 `templates/roadmap-proposal.template.md` 形成路线、阶段、依赖、范围与毕业成果。
2. 不在本阶段创建文章、目录或持久状态。
3. 展示完整提案并等待第一次确认；用户调整后重新展示受影响内容。
4. 确认后转入 `workflows/§03-design-course.md`。

失败路径：关键官方资料不可访问、主题边界无法确认或版本事实相互冲突时停止，不用推断补齐路线。
