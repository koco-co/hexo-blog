# 从开源项目开始课程

本工作流处理 GitHub URL、`owner/repo` 和成熟开源项目。开始前完整读取 `rules/research-policy.md` 与 `rules/curriculum-quality.md`。

## Phase 1：固定项目身份

1. 解析 canonical URL，确认目标 ref、完整 Commit、许可证、维护状态和核验日期。
2. 用户未指定学习深度时，默认覆盖“会使用、理解架构、读懂核心源码链路、能够调试与扩展”，不要求修改源码。
3. 区分官方仓库、镜像、Fork、已归档项目和同名包；身份不明确时停止。

完成信号：后续资料和文章都能追溯到同一项目与版本。

## Phase 2：建立项目模型

1. 阅读 README、官方文档、安装指南、架构说明、发布记录、贡献指南和测试入口。
2. 从源码核对技术栈、目录职责、关键输入输出、主调用链、扩展点和失败边界。
3. 需要完整源码时使用临时只读 checkout，并固定 Commit；持久 clone、安装依赖、运行项目或修改源码分别遵守用户确认和目标仓库规则。
4. 从 Issues、Discussions、Pull Requests 与问答社区提取高频配置、故障、设计争议和维护者解释，再与当前源码核验。

完成信号：核心切片、必要前置、运行边界和社区问题均有当前证据。

## Phase 3：形成路线提案

1. 按 `templates/roadmap-proposal.template.md` 形成从使用到源码的阶段路线。
2. 把贡献、最小 Patch 和上游协作列为可选分支，只有用户明确要求时加入必修路线。
3. 展示完整提案并等待第一次确认；确认前不创建课程文件。
4. 确认后转入 `workflows/§03-design-course.md`。

失败路径：仓库身份、许可证、目标 Commit 或关键源码无法核实时停止；不根据第三方教程重建项目事实。
