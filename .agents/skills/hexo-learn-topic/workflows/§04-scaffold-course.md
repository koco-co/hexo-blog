# 创建路线图与文章占位

本工作流只在文章地图第二次确认后执行。完整读取 `rules/article-tag-selection.md`、`templates/roadmap-post.template.md`、`templates/article-placeholder.template.md`、`templates/course-roadmap-created-reply.template.md`、`examples/course-roadmap-created-reply.example.md` 和 `checklists/course-acceptance.md`，并把 `assets/course-cover-reference.png` 作为系列封面的固定风格参考图。

## Phase 1：锁定写入范围

1. 目标目录固定为 `source/_posts/learn-topic/<主题路径段>/`；路径段应是简洁、稳定的单个目录名，不得是绝对路径、`.`、`..` 或包含路径分隔符，并避免与现有课程冲突。
2. 路线图和每篇文章都使用已确认的动态名称，但文件名必须是单个 `.md` basename：禁止绝对路径、路径分隔符、`.`、`..`、重复扩展名和解析后的父目录变化；合法中文和 Unicode 名称可以保留。
3. 对每个规范化绝对目标断言其父目录严格等于本课程目录；创建前逐个检查目标路径，不覆盖任何现有文件，冲突时停止并提交新路径建议。
4. 系列封面目标固定为现有目录 `source/img/picgo-images/<主题路径段>-course-cover.png`；创建前检查同名冲突，不覆盖已有图片。

完成信号：待创建文章与封面路径均与已确认文章地图一致，写入范围唯一。

## Phase 2：生成并验收系列封面

1. 在文章地图第二次确认后、准备占位文章前，调用当前平台可用的内置图像生成能力，为该系列生成一张候选封面；生成能力不可用时停止并报告，不静默使用随机图片，也不自动切换到需要凭据的外部调用。
2. 最终文件必须是 `1920 × 1080` 的 PNG；生成器输出尺寸不同时，在不改变构图语义的前提下规范化为该尺寸，项目中只保留最终封面。
3. 使用下面的固定提示词合同调用图像生成能力；`Image 1` 必须是 `assets/course-cover-reference.png`，它只约束版式、材质、霓虹密度和光影，不是待编辑图片：

   ```text
   Use case: stylized-concept
   Asset type: 16:9 Hexo learning-series cover
   Primary request: 为“{{简短系列名称}}”生成一张独立课程封面，使用文章地图冻结的主题内容完整替换参考图内容。
   Input images: Image 1 是风格与构图参考；只参考深色工业科技背景、中央发光主题徽章、顶部短标签带和底部大标题的视觉层级；不要复制其中的 Python 图标、Python 工具名、原文或水印。
   Scene/backdrop: 深蓝黑未来开发控制台与精密机械面板，具有真实层次、金属纹理和克制的青蓝、紫色及主题强调色霓虹。
   Subject: 中央放置一个准确、清晰、立体发光的“{{主题图标}}”主题标识，承载画面主焦点；使用与课程主题直接相关的结构或界面细节辅助表达。
   Composition/framing: 1920 × 1080 横向构图；中央主题标识约占画面高度 35%～45%；上方在安全区内均匀排列 4～5 个小图标与短标签；底部在安全区内放置唯一大标题；四周保留裁切余量。
   Lighting/mood: 电影级霓虹轮廓光、适度体积光和地面反射，清晰锐利但不过曝。
   Text (verbatim): 大标题“{{简短系列名称}}”；顶部标签依次为“{{短词 1}}”“{{短词 2}}”“{{短词 3}}”“{{短词 4}}”“{{短词 5，可选}}”。
   Constraints: 大标题和每个顶部标签都只出现一次并逐字准确；主题图标不得畸形；缩略图和移动裁切后仍能识别主标题与主题标识；使用参考图的信息密度和专业海报质感，但为当前主题重新设计全部内容。
   Avoid: 参考图中的 Python 图标与工具名（目标主题本身为 Python 时除外）；随机风景；人物或动漫主体；长副标题；未冻结的额外文字；乱码；水印；错误 Logo；廉价通用科技横幅；空旷单主体构图；过度光晕。
   ```

4. 生成后逐字检查大标题和全部顶部标签，检查主题标识准确性、参考图内容是否残留、中央 70% 安全区、缩略图辨识度和整体信息密度；任一项不合格时只针对该问题重新生成候选并复查，不把失败版本写入项目。
5. 验收通过后把唯一封面保存到 Phase 1 锁定的本地路径，并冻结该路径供路线图、占位文章和后续正式文章复用；除非用户明确要求替换，不再重新生成。

完成信号：项目最终只保留一张通过验收的 `1920 × 1080` PNG 系列封面，主标题、主题标识和 4～5 个课程关键词准确，视觉层级与固定参考一致但没有复制参考图主题内容，裁切安全且本地路径已冻结；为修复验收问题生成的候选不计为多篇或多封面交付。

## Phase 3：在隔离目录准备完整文章

1. 用 `mktemp -d` 创建本次专用隔离根；可以在其中使用 `hexo new --path`，但不得让当前不完整 scaffold 的中间结果进入真实 `source/_posts/`。
2. 在隔离根中把每篇补全为最终占位内容。路线图包含阶段、依赖、文章地图、状态、阅读顺序、完成标准和来源；同时按 `templates/course-contract.template.json` 把第二次确认前已经 Reviewer 审查的第一轮学习主题、可选篇、完整文章清单、入口 manifest、完整官方全集、逐项覆盖处置账本、旧接口迁移映射与集合摘要写入 `data/<主题路径段>.json`。契约必须使用 `schema_version: 2`、`course.public_article_contract: "v1"` 和模板默认的 `course.forbid_local_absolute_paths: true`，并无损保存每项的对象或主题、来源、版本状态、处置、主文章、目标章节、理由和验证状态。脚手架不得首次创建或改写映射，文章 Front Matter 禁止任何 `learn_topic_*` 内部字段。未发布文章只显示标题和状态，不生成指向不存在路由的链接。
3. 其他文章包含完整 Front Matter、隐藏的 `<!-- learn-topic-placeholder -->` 标记与确认后的文章合同，并使用布尔值 `published: false`。
4. 所有文章使用嵌套分类 `Learn Topic → <主题>`、统一 `series`、同一个本地 `cover`、与中文序号一致的 `series_order` 和 `{% course_series %}` 导航；不依赖标题或发布日期推断课程顺序，不填充正式讲解，不制造假代码、假 FAQ、假闪卡或无来源答案。占位文章只保留 `article-placeholder.template.md` 的职责、边界、正文块、标签选型、视觉复习和验收证据合同；每个正文块记录主承载、选择理由、直接可见内容和失败降级，但不填充正式正文。依赖、能力账本和来源清单留在路线图或课程契约，不复制进公开正文。
5. 在隔离根运行全仓库 lint 并逐文件读回，确认数量、路径、Front Matter、正文合同和 Skill 数据契约完全匹配；用一个不依赖当前对话的读回过程从 `data/<主题路径段>.json` 恢复 manifest、全集、五类处置、排除理由和文章分配，并对每项稳定标识、对象或主题、来源、版本状态、强制镜像、处置、主文章、目标章节、理由和验证状态执行字段级往返比较。集合不相等、字段丢失、旧 Front Matter 字段残留或 lint 非 `pass` 时不写入真实目录。

完成信号：隔离根中的路线图与占位文章数量、名称、顺序和大纲完全匹配确认结果，非路线图文章均有占位标记且为布尔值 `published: false`。

## Phase 4：失败安全地写入真实目录

1. 先逐篇写入完整的未发布文章，每次写入后立即读回并确认 `published` 的类型和值；不得先创建默认公开文件再补字段。
2. 所有未发布文章写入并核对成功后，最后写入可渲染路线图；路线图仍不得链接未发布路由。
3. 任一步失败时停止，报告本轮已创建的精确文件；没有写入路线图时，部分课程不会公开。已写入的占位必须保持 `published: false`，未经删除授权不自动移除。
4. 路线图写入后再次核对文件集合与隔离根一致；只删除本次精确创建且已核对的临时目录，不运行项目清理。

完成信号：真实目录全部文件与隔离根一致，路线图最后落盘，任一中断点都不会留下默认公开的半成品文章。

## Phase 5：验证并停止

1. 运行 `node .agents/scripts/audit.mjs lint --json`；任何具体文件错误都先修复并重跑，只有 `status: pass` 才继续。
2. 调用 `hexo-blog-maintenance` 的验证流程构建并在浏览器检查路线图文章；占位文章不作为已完成正文验收。
3. 构建后读回所有新文件，核对 `abbrlink`、`published`、`cover`、`series`、`series_order`、课程导航、分类和路线状态，并确认所有文章只引用同一张存在的本地封面。
4. 在桌面和移动视口检查路线图封面及缩略图裁切，确认主题文字或图标清晰、图片完成加载且无 404。
5. 按 `templates/course-roadmap-created-reply.template.md` 交付用户可识别的“学习路线图已创建”回复，只说明已创建的课程、学习顺序、图解与实验、闪卡重点和下一篇文章；不得混入目录树、文件路径、Front Matter、执行命令、审计结果、Reviewer 结论或验证状态。回复后停止，不得自动开始第一篇正文。

失败路径：任一封面生成、准备、写入、审计、构建或页面验证失败时停止，逐文件读回公开状态并修复后重跑受影响步骤；不得以 Butterfly 随机封面代替失败的系列封面。
