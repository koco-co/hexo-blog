# 继续课程并编写文章

本工作流默认完成一篇；用户明确授权批量完成时，仍按知识依赖顺序逐篇执行同一门禁。开始前完整读取 `rules/research-policy.md`、`rules/learning-article-quality.md`、`prompts/article-reviewer.agent.md` 和 `checklists/course-acceptance.md`。

## Phase 1：恢复课程状态

1. 读取路线图全文和其声明的文章路径；确认主题、版本、知识依赖顺序、`series_order`、状态与下一篇带占位标记且为 `published: false` 的文章。批量模式同时冻结本批次清单，但当前只写最前面的可执行文章。
2. 读取目标占位全文、前置文章和原始来源；只读检查官方资料是否发生版本或维护状态变化。
3. 路线结构需要实质变更时先提交修订预览并等待确认，不在单篇写作中悄悄改课。

完成信号：当前只有一个写入目标，前置满足，动态事实仍适用或已获修订确认；批量清单不会改变逐篇门禁。

## Phase 2：更新单篇资料与视觉预案

1. 针对本文重新阅读官方资料、相关源码、Issues/Discussions 与高质量问答。
2. 把社区问题分类为高频疑问、真实踩坑、误解、面试或拓展；技术答案与当前一手资料交叉核验。
3. 启动一次完整的 `hexo-blog-maintenance` 调用，由其生成文章结构与标签编排预案并等待用户确认。
4. 预案优先用 Mermaid、表格、图表、真实截图或本地图片表达关系、流程、状态、层级和精确比较；Mermaid 流程图按 `rules/learning-article-quality.md` 选择并注明 `LR` 或 `TD/TB` 及理由，不为装饰增加图片。

完成信号：该篇来源和视觉预案均已确认，核心信息不会被隐藏组件遮蔽。

## Phase 3：由维护 Skill 编写并验证未发布正文

1. 在同一次维护调用中按确认预案编写正文，暂时保留占位标记和 `published: false`，直到公开候选门禁通过。
2. 每篇围绕一个贯穿问题或案例展开，覆盖机制、完整示例、输出或验证、失败边界、踩坑、FAQ、自测和来源。
3. 保留与文章中文序号一致的 `series_order` 和 `{% course_series %}`，课程导航不得退回 Butterfly 的标题或日期排序。需要进入长期复习队列的 FAQ、面试题和自测使用 `flashcard`，为每题设置稳定且唯一的 `id`，并提供精简回答和详细解析；跨文章复用同一道题时只用 `flashcard_ref` 引用原始定义的 `id`，不得复制题目、回答或解析。补充说明、长代码、日志和其他不进入复习队列的内容使用 `folding`；只在原文阅读的章节末完整自测使用 `hideToggle`；先思考再揭晓使用 `hideBlock`；术语、命令和短答案使用 `hideInline`。
4. 核心结论、必要命令和安全风险直接展示；隐藏内容不使用会进入目录的 H1-H6 标题。
5. 正文不因篇幅追求重复解释，也不把目录、定义清单或未验证代码冒充干货。
6. 维护 Skill 继续拥有初稿验证责任：运行适用审计，在隔离副本使用 `--draft` 完成真实生成与浏览器验收，再把完整结果交回本 Skill；不得用不包含目标文章的普通构建完成调用。

完成信号：维护 Skill 的视觉、写作、标签、资源、草稿构建和浏览器门禁全部闭合，文章仍为未发布状态。

## Phase 4：Article Reviewer 查漏

1. 冻结用户需求摘要、路线图、目标文章、文章合同、来源清单和已执行验证。
2. 启动只读、无父对话历史的独立子代理，并只提供冻结材料与 `prompts/article-reviewer.agent.md`。
3. Reviewer 检查文章相对于路线是否遗漏、事实是否有依据、机制与示例是否完整、视觉是否代替长段文本、FAQ 与自测是否有效。
4. Reviewer 不修改文章。存在阻塞项时重新调用 `hexo-blog-maintenance` 修订正文并重跑受影响审计、草稿构建和浏览器场景，再启动独立复查。

完成信号：Reviewer 为 PASS 或仅剩已披露且不影响目标的非阻塞项。

## Phase 5：隔离验证公开候选并提升真实状态

1. 把当前课程复制到新的隔离候选目录；只在候选副本中将目标文章改为 `published: true`，并把路线图中目标文章的纯文本标题、状态和前置关系一起更新为最终链接与已完成状态。
2. 在候选副本运行普通 Hexo 生成、发布级内容审计和公开路由浏览器检查，覆盖桌面、移动端、明暗主题、目录、代码、图片、展开交互、控制台和资源错误。
3. 候选的普通生成、发布审计和浏览器检查全部通过后，才用一次受控修改删除真实文章的占位标记、同步 `published: true` 与路线图中目标文章的状态、链接和前置关系，并立即读回核对；此状态提升是正文工作流的自动收尾，不等待用户提醒。
4. 在真实项目运行普通构建、发布级内容审计和最终路由冒烟检查。任何一步失败时，立即用一次受控修改恢复占位标记与 `published: false`，把路线图中目标文章恢复为无链接的阻塞状态，并逐文件读回。
5. 真实状态恢复后运行普通构建以覆盖本轮可能生成的公开路由，再运行内容审计；恢复构建仍失败时停止并明确标记 `public/`、`db.json` 可能不一致，禁止部署，不通过未授权的 `npm run clean` 掩盖问题。

完成信号：`published: true` 的首次真实写入晚于全部隔离公开候选证据，文章 Front Matter、路线图状态、链接和最终生成结果一致；单篇模式随后停止，批量模式按冻结顺序进入下一篇。
