# 继续课程并编写文章

本工作流默认完成一篇；用户明确授权批量完成时，仍按知识依赖顺序逐篇执行同一门禁。开始前完整读取 `rules/research-policy.md`、`rules/learning-article-quality.md`、`rules/published-article-contract.md`、`rules/article-tag-selection.md`、`references/butterfly-tag-usage.md`、`prompts/article-reviewer.agent.md` 和 `checklists/course-acceptance.md`。

## Phase 1：恢复课程状态

1. 读取路线图全文和其声明的文章路径；确认主题、版本、知识依赖顺序、`series_order`、状态与下一篇带占位标记且为 `published: false` 的文章。批量模式同时冻结本批次清单，但当前只写最前面的可执行文章。
2. 从 `data/<主题路径段>.json` 的 schema v2 课程契约恢复第一轮学习主题、可选篇、完整文章清单、入口 manifest、官方能力全集、覆盖处置账本和原始来源，再逐项恢复对象或主题、来源、版本状态、强制镜像、处置、主文章、目标章节、理由和验证状态并做字段级往返比较；然后读取目标占位全文与前置文章。无法仅凭项目文件恢复、字段丢失、集合不相等、文章映射不一致或课程 Front Matter 出现任何 `learn_topic_*` 内部字段时停止。只读检查官方资料、公开成员及弃用状态是否变化。
3. 路线结构需要实质变更时先提交修订预览并等待确认，不在单篇写作中悄悄改课。

完成信号：当前只有一个写入目标，前置满足，动态事实仍适用或已获修订确认；批量清单不会改变逐篇门禁。

## Phase 2：更新单篇资料与视觉预案

1. 针对本文重新阅读官方资料、相关源码、Issues/Discussions 与高质量问答。
2. 从官方索引重新提取该篇对象或主题的条目，与账本分配做全量差集；新增、移除或弃用变化会改变文章范围时先提交修订预览。
3. 把社区问题分类为高频疑问、真实踩坑、误解、面试或拓展；技术答案与当前一手资料交叉核验。
4. 重新检查本文的主问题、心智模型、操作链路、失败边界与 H2/H3 层级。当前文章出现过载、过轻、重复归属或必须改变第一轮主题时停止，按 Phase 1 的路线修订门禁处理，不能用更多折叠标签掩盖结构问题。
5. 按 `rules/article-tag-selection.md` 生成当前标签能力快照，冻结注册、容器性、配置门禁和运行资源状态。启动一次完整的 `hexo-blog-maintenance` 调用，由其按 `rules/published-article-contract.md` 和 `rules/article-tag-selection.md` 生成逐正文块结构与标签编排预案并等待用户确认；预案只列出分配给该篇的前四类正文处置条目及计划落点，明确不纳入项不进入单篇写作。
6. 每个正文块的预案写明读者任务、核心内容、主承载、选型理由、直接可见信息和失败降级。预案必须从完整目录比较合适标签，不能只在 `note`、`folding`、`tabs` 三者之间选择；也不能为展示标签丰富度硬塞无关组件。
7. 预案优先用 Mermaid、表格、图表、真实截图或本地图片表达关系、流程、状态、层级和精确比较；Mermaid 流程图按 `rules/learning-article-quality.md` 选择并注明 `LR` 或 `TD/TB` 及理由，不为装饰增加图片。

完成信号：该篇来源和视觉预案均已确认，核心信息不会被隐藏组件遮蔽。

## Phase 3：由维护 Skill 编写并验证未发布正文

1. 在同一次维护调用中按确认预案编写正文，暂时保留占位标记和 `published: false`，直到公开候选门禁通过。
2. 每篇围绕一个贯穿问题或案例展开，逐项实现账本分配，覆盖机制、完整示例、输出或验证、失败边界、踩坑和主题复习；正文先用有语义的块级标签定位本节问题，不输出课程进度、前置文章、能力 ID 或内部合同。每个解释块必须落实已确认的主承载、可见性和降级方案并通过逐块审计；重复组件按 `rules/article-tag-selection.md` 重新比较候选。只有存在真实长期记忆价值时才加入 FAQ/闪卡，入门路线不得加入。末尾参考资料按 `rules/learning-article-quality.md` 使用分组资料卡片，并为每张卡片提供同域或同组织官方图标。
3. 保留与文章中文序号一致的 `series_order` 和 `{% course_series %}`，课程导航不得退回 Butterfly 的标题或日期排序。Mermaid 图必须使用 `{% mermaid %}` 与 `{% endmermaid %}`，不得使用 Markdown Mermaid 围栏。主题、进阶和实战文章如保留 `常见问题`，其中必须使用 `flashcard` 或 `flashcard_ref`；入门路线删除 FAQ 和闪卡。面试题和自测只有在确实需要进入长期复习队列时才使用闪卡。每题设置稳定且唯一的 `id`、单一卡组和 `priority:1|2|3`，并提供精简回答和详细解析；跨文章复用同一道题时只用 `flashcard_ref` 引用原始定义的 `id`，不得复制题目、回答或解析。概念深入解释、补充说明、长代码、日志和其他不进入复习队列的内容可以使用 `folding`；多平台或多安装方式使用 `tabs`；其他内容按完整标签目录的语义选择。`issues` 关闭时禁止使用，Butterfly `series` 不得替代 `course_series`。
4. 核心结论、必要命令和安全风险直接展示；隐藏内容不使用会进入目录的 H1-H6 标题。
5. 正文不因篇幅追求重复解释，也不把目录、定义清单或未验证代码冒充干货。
6. 维护 Skill 继续拥有初稿验证责任：运行适用审计，在隔离副本使用 `--draft` 完成真实生成与浏览器验收，再把完整结果交回本 Skill；不得用不包含目标文章的普通构建完成调用。

完成信号：维护 Skill 的视觉、写作、标签、资源、草稿构建和浏览器门禁全部闭合，文章仍为未发布状态。

## Phase 4：Article Reviewer 查漏

1. 冻结用户需求摘要、路线图、目标文章、文章合同、逐正文块结构与标签计划、按 `rules/article-tag-selection.md` 生成的当前标签能力快照、官方能力全集、覆盖处置账本、该篇分配、来源清单和已执行验证。
2. 每次只启动一个只读、无父对话历史的独立子代理审查一篇文章，并完整提供冻结材料与 `prompts/article-reviewer.agent.md`；禁止把多篇合并为一个审查批次。
3. Reviewer 先从官方索引独立复算该篇对象或主题的条目，与账本及正文做全量差集，再检查事实、机制、示例、视觉、FAQ 与自测。Prompt 或任一覆盖输入缺失时返回 `INSUFFICIENT_INFORMATION`，不能凭已有正文给出 `PASS`。
4. Reviewer 不修改文章。存在阻塞项时重新调用 `hexo-blog-maintenance` 修订正文并重跑受影响审计、草稿构建和浏览器场景，再启动独立复查。

完成信号：Reviewer 为 PASS 或仅剩已披露且不影响目标的非阻塞项。

## Phase 5：隔离验证公开候选并提升真实状态

1. 把当前课程复制到新的隔离候选目录；只在候选副本中将目标文章改为 `published: true`，并把路线图中目标文章的纯文本标题、状态和前置关系一起更新为最终链接与已完成状态。
2. 在候选副本运行普通 Hexo 生成、发布级内容审计和公开路由浏览器检查，覆盖桌面、移动端、明暗主题、目录、代码、图片、folding 展开、tabs 切换、隐藏答案、媒体降级、键盘焦点、PJAX、控制台和资源错误；只检查本文真实使用的交互类型。
3. 候选的普通生成、发布审计和浏览器检查全部通过后，才用一次受控修改删除真实文章的占位标记、同步 `published: true` 与路线图中目标文章的状态、链接和前置关系，并立即读回核对；此状态提升是正文工作流的自动收尾，不等待用户提醒。
4. 在真实项目运行普通构建、全仓库 lint 和最终路由冒烟检查。lint 非 `pass` 时按具体文件修复并重跑，不得交给用户验收。任何一步失败时，立即用一次受控修改恢复占位标记与 `published: false`，把路线图中目标文章恢复为无链接的阻塞状态，并逐文件读回。
5. 真实状态恢复后运行普通构建以覆盖本轮可能生成的公开路由，再运行内容审计；恢复构建仍失败时停止并明确标记 `public/`、`db.json` 可能不一致，禁止部署，不通过未授权的 `npm run clean` 掩盖问题。

完成信号：`published: true` 的首次真实写入晚于全部隔离公开候选证据，文章 Front Matter、路线图状态、链接和最终生成结果一致；单篇模式随后停止，批量模式按冻结顺序进入下一篇。
