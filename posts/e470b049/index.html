主线已经建立 HTTP、TCP、TLS、IP 和排障模型；本文把 WebSocket、DoH/DoT、IPsec、VXLAN 以及网络治理和 HTTP 扩展放回各自的层次，解释它们解决什么问题、引入什么边界，以及何时值得继续深入。

扩展协议地图

先定位“改变了哪一层”

    flowchart TD
  MAIN[主线：DNS/IP/TCP/TLS/HTTP/排障]
  MAIN --> WS[WebSocket：应用层升级与消息帧]
  MAIN --> DOH[DoH/DoT：DNS 查询的安全承载]
  MAIN --> IPSEC[IPsec：IP 层安全架构]
  MAIN --> VXLAN[VXLAN：数据中心二层覆盖到三层 underlay]
  WS -->|依赖 HTTP Upgrade、TLS、浏览器 Origin| HTTPBASE[HTTP/TLS 基础]
  DOH -->|依赖 DNS、TLS/HTTP、证书| NAME[名称解析基础]
  IPSEC -->|依赖 IP、路由、密钥协商| IPBASE[IP 基础]
  VXLAN -->|依赖以太网、UDP、路由和 MTU| FABRIC[局域网与 IP 基础]
主题 它扩展的对象 先学什么 不要把它误认为
WebSocket HTTP 之后的双向应用消息 HTTP Upgrade、TLS、浏览器 Origin “TCP 自动变成消息队列”
DoH DNS 查询通过 HTTPS 发送 DNS 递归、HTTPS、HTTP/2/3 “所有 DNS 都被隐藏”
DoT DNS 查询通过 TLS 长连接发送 DNS、TLS、端口 853 语境 “比 DoH 在所有网络都更快”
IPsec IP 包的认证/加密和隧道 路由、策略、密钥管理 “TLS 的另一个名字”
VXLAN 二层帧跨三层网络的覆盖封装 VLAN、UDP、MTU、VTEP “把任何二层网络无限延伸”

应用协议

WebSocket 的升级边界

WebSocket 通常从 HTTP/1.1 Upgrade 请求开始，服务端返回 101 Switching Protocols 后，双方不再把后续字节当作普通 HTTP 请求/响应，而是进入 WebSocket 帧语义。它仍然依赖底层 TCP（或安全的 wss 连接依赖 TLS），但应用层消息边界由 WebSocket 帧定义。

    sequenceDiagram
  participant B as 浏览器
  participant S as WebSocket 服务
  B->>S: GET /chat + Upgrade: websocket + Sec-WebSocket-Key
  S-->>B: 101 Switching Protocols + Sec-WebSocket-Accept
  B->>S: WebSocket text/binary frame
  S-->>B: WebSocket frame
  Note over B,S: 后续不再按普通 HTTP 请求/响应配对

关键边界：

  • 101 是升级握手的 HTTP 结果，不是普通业务成功码；
  • WebSocket 有自己的帧、ping/pong、close 和掩码规则；
  • 浏览器会携带 Origin，服务端需要在应用层决定是否允许来源；
  • 代理、负载均衡、空闲超时和连接复用策略都可能影响长连接；
  • WebSocket 不自动提供消息持久化、重试、顺序业务语义或鉴权撤销。

复现时先用服务端和客户端都明确支持 WebSocket 的测试夹具；只用 curl 发一个 Upgrade 头，不代表已经完成了后续 WebSocket 帧通信。观察 101、连接保持、ping/pong 和 close 时序，比只看页面“连接成功”更有证据价值。

DoH 与 DoT 的取舍

DoH 把 DNS 查询放进 HTTPS，通常复用 HTTP/2 或 HTTP/3 的连接和端口；DoT 把 DNS 查询放进 TLS，通常使用专用的 TLS 服务端口。二者都能保护客户端到指定解析器之间的查询内容，但不能自动隐藏访问目标、终端行为、解析器日志或后续连接。

维度 DoH DoT
承载 HTTPS TLS 上的 DNS
常见入口 与 Web 流量相近的 HTTPS 端口 专用 DNS over TLS 端口
中间网络可见性 更像普通 HTTPS，策略识别更难 更容易按专用端口识别/治理
部署形态 浏览器、操作系统或应用指定 HTTPS resolver 系统 resolver 或网络设备指定 TLS resolver
取舍 易穿过只允许 Web 的网络，但可能集中化 语义直接、网络治理清晰，但专用端口可能被阻断

选择时要问：谁运营解析器、失败时是否回退明文、如何验证证书、是否需要企业审计和家长控制、客户端是否会绕过本地策略。不要把“加密了 DNS”扩展成“端到端所有流量都匿名”。

名称解析和连接证据

DoH/DoT 解决的是 DNS 查询承载，不能替代后续目标服务的 TCP/QUIC、TLS 和 HTTP 证据。排障时可以把链路拆成：应用选择 resolver → 解析器返回地址 → 客户端连接地址 → 目标服务建立安全协议。若只看到 DoH 成功，不代表目标 IP 可达。

网络安全与覆盖

IPsec 的安全模型

IPsec 在 IP 层提供安全架构，核心是按策略决定哪些流量需要保护，并通过安全关联和密钥管理确定如何认证/加密。ESP 可以提供机密性、完整性和认证等能力；AH 关注认证/完整性但在 NAT 等环境中有现实边界。传输模式通常保护 IP 载荷，隧道模式把整个原始 IP 包封装进新的 IP 包。

    flowchart LR
  POLICY[安全策略选择流量] --> SA[Security Association 与密钥]
  SA --> ESP[ESP/AH 处理]
  ESP --> TRANS[传输模式：保护载荷]
  ESP --> TUNNEL[隧道模式：封装原始 IP 包]
  TUNNEL --> PEER[对端解封装并按策略交付]

IPsec 与 TLS 的边界不同：TLS 通常由应用连接端点或代理终止，IPsec 可以保护一段网络到网络、主机到网络的 IP 路径。两者可以叠加，也可能由不同团队、设备和信任域管理。看到“隧道建立”不能直接推断应用授权和端点身份已经完成。

VXLAN 隧道

VXLAN 用 VNI 标识覆盖网络，把原始二层帧封装在 UDP/IP 外层，常见 VTEP 负责封装和解封装。底层 underlay 只需要为 VTEP 之间提供三层可达性，overlay 则让虚拟机或租户看到逻辑二层网络。

    flowchart LR
  VM1[租户主机 A] --> VTEP1[VTEP 1]
  VTEP1 -->|外层 IP/UDP + VNI| UNDERLAY[三层 Underlay]
  UNDERLAY --> VTEP2[VTEP 2]
  VTEP2 --> VM2[租户主机 B]
  VTEP1 -.Overlay 广播/组播或控制面学习.-> VTEP2

VXLAN 的排障重点包括 VTEP 外层 IP 可达性、UDP 端口、VNI、封装后的 MTU、控制面/数据面学习和跨租户隔离。它不是让二层广播消失的魔法；广播、未知单播和组播在 overlay 中仍需要复制、控制面或硬件策略，规模化时必须关注泛洪范围。

网络治理与协议扩展

DSCP 与 QoS

DSCP 位于 IP 服务质量字段，表达流量分类或转发处理意图；它不是带宽保证，也不是加密认证。标记是否被保留、队列是否按标记配置、运营商是否重写，都要在具体路径上验证。抓包中看见 DSCP 值，只能证明包带了标记，不能证明获得了某种时延或带宽。

IPv4 组播

IPv4 组播让一个发送者面向组地址发送，接收者通过组成员关系加入；它不同于广播，也不是自动跨所有路由器传播。交换机、IGMP、路由协议和边界策略决定组播是否有效。测试时应使用授权的隔离组地址和明确 TTL，避免产生不可控的跨网流量。

OSPF 与 BGP

OSPF 常用于自治系统内部的链路状态路由，BGP 用于自治系统之间以及更广泛的策略路由。它们影响的是路由控制平面，不是 TCP 三次握手的替代品。遇到“某个前缀走错路”时，先看路由表和下一跳，再根据网络权限进入邻居、策略、前缀通告和收敛证据。

WebDAV 与 102

WebDAV 扩展了 HTTP 的资源管理方法和属性语义，102 Processing 是其历史语境中的处理中状态；它们不能被当作普通 API 的通用状态或方法约定。使用新方法或状态时，应查规范和 IANA 注册表，并说明客户端、代理和服务端是否真正支持。

扩展主题的边界

面对一个陌生协议时，先确定它回答的问题、所属层次、官方规范、关系图和可复现实验。旧笔记可以帮助发现问题，但不能替代当前规范；“已经写进文章”也不能替代构建、浏览器和真实环境证据。

Q01高频
#计算机网络#HTTP#GET#POST#PUT#PATCH
问题:

GET、POST、PUT、PATCH、DELETE 的核心边界是什么？

回答：

GET 获取，POST 提交处理或创建，PUT 以给定表示创建/替换，PATCH 做部分修改，DELETE 删除目标当前关联；具体资源语义仍由 API 契约定义。

解析：

不要把 POST 等同于“有请求体”、PUT 等同于“全量更新”的绝对规则。方法语义、幂等性和应用接口设计要一起阅读。

这些术语最好分列判断：

维度 问的是什么 例子
安全性 预期是否改变目标状态 GET 通常安全
幂等性 重复执行的预期效果 PUT 通常可幂等
可缓存性 响应能否被缓存复用 仍受字段和上下文影响

方法名称不能替代 API 契约；状态码也只能说明 HTTP 层，不说明 DNS/TCP/TLS 已全部成功。

Q02高频
#计算机网络#HTTP#Cookie#CORS

Cookie、同源策略和 CORS 分别解决什么问题？

点击查看答案
Q02高频
#计算机网络#HTTP#Cookie#CORS
问题:

Cookie、同源策略和 CORS 分别解决什么问题？

回答：

Cookie 管理 HTTP 状态，同源策略限制脚本跨源交互，CORS 让服务端声明哪些跨源浏览器上下文可被允许。

解析：

CORS 不是认证，也不是让所有客户端自动遵守的防火墙。curl 通常不会执行浏览器同源策略，因此 curl 成功不能证明 Fetch 成功。

浏览器问题需要保留请求上下文：

服务端的许可字段、凭据模式和实际响应读取权限分别决定预检、发送和脚本可见性；curl 成功不等于浏览器上下文也会成功。

Q03高频
#计算机网络#QUIC#UDP#TLS 1.3

QUIC 为什么不能简单理解为“没有连接的 UDP”？

点击查看答案
Q03高频
#计算机网络#QUIC#UDP#TLS 1.3
问题:

QUIC 为什么不能简单理解为“没有连接的 UDP”？

回答：

QUIC 在 UDP 上实现了连接 ID、确认、丢包恢复、拥塞控制、独立流和加密，并集成 TLS 1.3 握手。

解析：

UDP 只是 QUIC 的数据报封装入口。HTTP/3 依赖 QUIC 的传输能力，因此“使用 UDP”不等于没有可靠性或安全状态。

一次 HTTPS 协商要把身份、协议和密钥分开核对：

观察项 主要回答 不是它负责的
证书链/SAN 服务端身份是否可信且匹配 业务授权
SNI 服务端选择哪个虚拟主机 信任本身
ALPN 选 h2、h3 等应用协议 证书匹配
TLS 密钥 传输机密性和完整性 HTTP 方法语义

#计算机网络#证书#SNI#ALPN

证书链、主机名校验、SNI 和 ALPN 各自解决什么问题？

Q04高频
#计算机网络#证书#SNI#ALPN
问题:

证书链、主机名校验、SNI 和 ALPN 各自解决什么问题？

回答：

证书链验证信任路径，主机名校验证书是否属于目标，SNI 帮服务端选择虚拟主机，ALPN 协商应用协议版本/协议。

Q05高频
#计算机网络#DNS#TCP#TLS#HTTP

如何区分 DNS 失败、TCP 拒绝、TLS 证书失败和 HTTP 502？

点击查看答案
Q05高频
#计算机网络#DNS#TCP#TLS#HTTP
问题:

如何区分 DNS 失败、TCP 拒绝、TLS 证书失败和 HTTP 502？

回答：

DNS 失败没有目标 IP，TCP 拒绝没有建立连接，TLS 失败通常 TCP 已建立但证书/握手未通过，502 则说明某个 HTTP 网关已经返回响应。

解析：

错误字符串可能随客户端变化，必须结合 DNS 查询、SYN/RST、TLS 握手和响应头判断，不要把所有现象称为“网络不通”。

可把错误放到一条时间线上：

每个错误字符串都要回到对应报文、响应头或服务端日志；不要把缺少 HTTP 响应的失败写成 4xx/5xx。

建议复习顺序是：先回答方法/协议边界，再回答 TLS 与证书，最后把扩展协议放回 DNS、IP 和排障证据链。若无法解释 HTTP Upgrade、证书主机名或 UDP/QUIC 的连接状态，就暂缓进入 WebSocket、DoH/DoT 或 VXLAN 的实现细节。

常见问题

Q06高频
#计算机网络#WebSocket#HTTP Upgrade

WebSocket 是不是“更快的 HTTP”？

点击查看答案
Q06高频
#计算机网络#WebSocket#HTTP Upgrade
问题:

WebSocket 是不是“更快的 HTTP”？

回答：

不是。它通常先通过 HTTP Upgrade 建立入口，随后使用不同的帧和长连接语义。

解析：

性能还取决于代理、心跳、消息大小、重连和服务端资源，不能只按协议名称比较快慢。

WebSocket 的切换点可以用请求头观察：

阶段 看到什么 语义
建立入口 HTTP Upgrade 请求/响应 从 HTTP 进入 WebSocket
建立后 WebSocket 帧和长连接 不再按普通 HTTP 请求/响应逐次交互

因此“更快的 HTTP”既混淆了协议边界，也忽略了心跳、重连和代理资源。

Q07中频
#计算机网络#DoH#DoT#DNS

DoH 比 DoT 更安全吗？

点击查看答案
Q07中频
#计算机网络#DoH#DoT#DNS
问题:

DoH 比 DoT 更安全吗？

回答：

不能脱离威胁模型比较。二者都可以保护客户端到解析器的查询传输，但信任、日志、端点策略、治理和回退行为决定实际风险。

解析：

DoH 更像 HTTPS，DoT 的专用端口更容易被识别和治理；加密查询不等于匿名化所有访问。

两者都保护客户端到解析器的查询传输，但治理形态不同：

方案 外观 需要额外核对
DoH HTTPS 流量 端点、代理、日志和回退
DoT 专用 TLS 端口 端口策略、识别和端点

加密查询不等于匿名化访问，也不自动改变解析器的信任与留存策略。

Q08高频
#计算机网络#IPsec#HTTPS#安全边界

IPsec 和 HTTPS 需要同时使用吗？

点击查看答案
Q08高频
#计算机网络#IPsec#HTTPS#安全边界
问题:

IPsec 和 HTTPS 需要同时使用吗？

回答：

它们保护的边界不同，是否叠加取决于网络拓扑和威胁模型。IPsec 可以保护网络路径，HTTPS 保护应用连接。

解析：

IPsec 隧道建立也不替代 HTTP 认证与授权；“链路加密”与“应用身份”不是同一个结论。

先标出保护边界：

技术 主要保护 仍需单独验证
IPsec 网络路径/隧道 应用认证与授权
HTTPS 应用连接到 TLS 终止点 终止点之后的内部链路

是否叠加取决于拓扑和威胁模型，不是“加密越多越安全”的抽象竞赛。

#计算机网络#VXLAN#VTEP#MTU
问题:

VXLAN 能解决所有 VLAN 扩展问题吗？

回答：

不能。它增加覆盖封装和规模化隔离能力，但引入 VTEP、MTU、控制面、泛洪和 underlay 可达性问题。

解析：

是否采用应由租户数量、故障域、控制面和运维能力决定，而不是只看 VNI 的数量空间。

VXLAN 扩展的是覆盖网络的隔离和规模，不会删除底层约束：

新增能力 新增边界
VNI 更大的租户标识空间
VTEP 封装/解封装与可达性
Overlay 需要额外 MTU、控制面和泛洪治理
