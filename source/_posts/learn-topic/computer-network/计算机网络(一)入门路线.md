## 自测与闪卡

入口篇的闪卡只负责课程地图、分层和答题框架；具体 TCP、HTTP、三次握手和抓包问题在后续文章中复习，避免入口卡片复制正文。

{% flashcard basic id:CN-NET-001 deck:"计算机网络" priority:1 tags:"网络模型,学习地图" %}
--- question
分析一个网络现象时，为什么要同时看目标、路径和语义三条轴？
--- answer
目标回答数据要交给谁，路径回答如何到达，语义回答到达后如何被协议和应用解释。
--- explanation
只看 IP 目标可能漏掉下一跳和端口，只看路径可能漏掉 HTTP/TLS 语义。三条轴能把地址、设备、传输和应用证据串起来。
{% endflashcard %}

{% flashcard basic id:CN-NET-002 deck:"计算机网络" priority:2 tags:"设备边界,分层" %}
--- question
交换机、路由器、防火墙和应用服务分别主要改变哪种网络边界？
--- answer
交换机处理二层帧和广播域内转发，路由器处理三层下一跳，防火墙按策略限制流量，应用服务处理端口之上的协议语义。
--- explanation
设备可能集成多种功能，回答时应按实际启用的转发、策略和终止行为描述，不要只按设备名称贴标签。
{% endflashcard %}

{% flashcard basic id:CN-NET-003 deck:"计算机网络" priority:1 tags:"封装,解封装" %}
--- question
网络通信中的封装和解封装分别发生了什么？
--- answer
发送端各层把自己的控制信息加到载荷外，接收端各层读取并消费对应字段，再把载荷交给上层。
--- explanation
中间交换机通常只读取链路层帧和 VLAN 上下文，路由器会重建下一跳链路帧；HTTP 内容不会在每一跳都被所有设备解析。
{% endflashcard %}

{% flashcard basic id:CN-NET-004 deck:"计算机网络" priority:1 tags:"面试题,答题框架" %}
--- question
网络面试题的“字段—状态—机制—边界”答题框架怎么用？
--- answer
先指出报文或日志字段，再说明状态变化，接着解释机制目的，最后列出还需验证的边界和证据。
--- explanation
这个顺序能避免把现象直接归因于某个设备或协议。三次握手、HTTP 502、DNS 失败和抓包题都可以复用。
{% endflashcard %}

{% flashcard basic id:CN-NET-005 deck:"计算机网络" priority:1 tags:"OSI,TCP-IP,分层" %}
--- question
OSI 模型和 TCP/IP 模型在学习中应如何使用？
--- answer
把它们当作定位职责和证据的抽象坐标，而不是要求每个现实协议严格只属于一层。
--- explanation
分层帮助回答“谁读取什么字段、边界在哪里”；ARP、TLS、QUIC 和防火墙等跨边界主题必须同时说明其实际承载和语义。
{% endflashcard %}

{% flashcard basic id:CN-NET-006 deck:"计算机网络" priority:2 tags:"课程路线,依赖" %}
--- question
为什么课程按局域网 → IP → UDP/TCP → HTTP → 现代 HTTP → 排障推进？
--- answer
后一个主题依赖前一个主题的地址、下一跳、传输状态和应用语义，按依赖顺序才能把抽象现象还原为可观察证据。
--- explanation
进阶路线和综合实战放在主线之后；它们复用前置闪卡，不用更多名词替代基础机制。
{% endflashcard %}

{% flashcard basic id:CN-ROADMAP-001 deck:"计算机网络" priority:2 tags:"入门路线,学习顺序" %}
--- question
为什么课程文章要按依赖顺序逐篇完成，而不是一次公开全部占位内容？
--- answer
因为每篇正文都必须同时完成前置概念、图表、可复现实验、失败边界和闪卡校验，未完成的占位文章不能冒充可学习正文。
