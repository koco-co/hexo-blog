{% note primary flat %}
结构化输出解决“结果长什么样”，工具调用解决“模型请求做什么”；二者都不能直接授予业务权限。本节用一个本地天气查询 fixture 验证 JSON Schema、工具参数、调用 ID、权限、超时、重复调用和拒答路径。
{% endnote %}

<!-- concept-story:start -->
一个助手收到“查一下上海天气”，模型返回了一个看似正确的函数调用。工程师因为调用名和参数都来自模型，就直接执行了；下一次模型把城市改成内部站点，又复用了上一次的调用 ID，系统仍然把请求当成正常天气查询。

团队后来把流程拆成四道门：先解析结构，再校验 schema，再检查业务权限与截止时间，最后用幂等键执行工具并回传结果。模型可以提出工具调用，但只有应用的策略层能决定这个调用是否真的发生。
<!-- concept-story:end -->

## Schema校验

### 字段校验

结构化输出至少有两层：

| 层 | 要检查什么 | 失败时的动作 |
| --- | --- | --- |
| 语法 | 是否是合法 JSON，字符串是否完整 | 返回 `parse_error`，不进入业务逻辑 |
| 形状 | 必需字段、类型、枚举、额外字段 | 返回 `schema_error`，要求重新生成或降级 |
| 语义 | 数值范围、字段之间的关系、证据是否存在 | 返回 `business_validation_error` |
| 安全 | 字符串是否包含越权目标、注入内容或不允许的资源 | 返回 `policy_error`，不执行副作用 |

OpenAI、Anthropic 和 Gemini 都提供不同形式的结构化或工具输出能力；即使 Provider 能约束输出形状，应用仍须验证业务规则。`response_format`、JSON Schema 或工具参数 schema 是“机器可解析”的边界，不是“业务一定正确”的证明。

### 工具与结果

工具协议可以抽象成以下状态，而不是一个 `call()` 函数：

```text
模型输出 function_call
        │
        ▼
解析名称与参数 ──失败──> schema_error
        │
        ▼
权限、资源、截止时间 ──失败──> policy/timeout
        │
        ▼
幂等执行 ──重复──> replay cached result
        │
        ▼
tool_result 回传模型并记录审计字段
```

不同 API 的外层名称可能不同：OpenAI Responses 将工具请求作为 `output` 项目，Anthropic Messages 使用 `tool_use` 内容块，Gemini Interactions 使用执行步骤和工具结果。统一层只抽象稳定语义：`call_id`、工具名、参数、授权结果、执行状态和结果；原始块仍要保存，不能用一个字符串字段抹平 Provider 差异。

工具结果也必须回到原来的调用关联上。不要按“最后一个工具”或数组位置猜测对应关系；至少使用调用 ID、工具名和版本化参数摘要校验关联。

## 工具执行

### 执行控制

{% note warning flat %}
天气查询虽然是读操作，仍然适合练习完整执行门禁：参数合法、工具在白名单、请求者有权限、目标资源可访问、截止时间未过、调用 ID 没有冲突。写数据库、发邮件、退款或删除文件时，必须在这套门禁之外增加确认、审计和更严格的人工/服务策略。
{% endnote %}

| 控制项 | 作用 | 最小证据 |
| --- | --- | --- |
| schema | 防止缺字段、错类型和额外参数 | 解析后的参数和校验结果 |
| allowlist | 防止模型调用未声明工具 | 工具名、版本和允许动作 |
| authorization | 防止模型越过用户/租户权限 | actor、资源范围和策略决定 |
| deadline | 防止慢工具占满请求 | 开始时间、预算、超时状态 |
| idempotency | 防止重试造成重复副作用 | 稳定调用 ID、参数摘要和缓存结果 |
| audit | 让决定可以复盘 | 请求、策略、结果和脱敏错误 |

幂等键不能只取模型生成的任意文本。应用应定义键的生命周期和冲突策略：同一个键、同一组参数可以重放缓存结果；同一个键换了参数则拒绝为 `conflict`，避免把两次不同业务动作误合并。

### 授权边界

模型输出只是建议动作，应用授权是独立步骤：

1. 读取模型调用块，不执行其中的代码或自然语言指令。
2. 将工具名映射到本地注册表，未知工具直接拒绝。
3. 用严格 schema 解析参数，拒绝缺字段、未知字段和错误类型。
4. 根据真实请求者、租户、资源和动作做权限判断。
5. 应用超时和幂等策略，记录决定，再调用工具。
6. 将脱敏的 `tool_result` 作为下一轮模型输入，不把内部凭据或策略细节回传。

## 最小实践

### 准备输入

{% note info flat %}
下列代码只运行本地天气工具夹具，不安装 SDK、不访问网络、不读取环境变量，也不包含真实凭据。`MODEL_TOOL_OUTPUT` 模拟模型提出的调用；`authorize_and_execute` 才是应用的执行边界。天气数据是合成结果，不能证明任何线上天气服务可用。
{% endnote %}

### 执行步骤

```python
import copy
import json

WEATHER_SCHEMA = {
    "required": {"city": str, "units": str},
    "allowed_units": {"celsius", "fahrenheit"},
}
ALLOWED_CITIES = {"Shanghai", "Beijing"}
TOOL_REGISTRY = {"get_weather": {"scope": "weather:read", "version": "1"}}
EXECUTION_CACHE = {}
EXECUTION_LOG = []

MODEL_JSON_OUTPUT = '{"city":"Shanghai","temperature_c":22,"source":"fixture"}'
MODEL_TOOL_OUTPUT = {
    "type": "function_call",
    "call_id": "weather_call_001",
    "name": "get_weather",
    "arguments": {"city": "Shanghai", "units": "celsius"},
}


def fail(code, detail):
    raise ValueError(f"{code}:{detail}")


def parse_json_output(raw):
    try:
        value = json.loads(raw)
    except json.JSONDecodeError as error:
        fail("parse_error", str(error))
    if not isinstance(value, dict):
        fail("schema_error", "result must be an object")
    required = {"city": str, "temperature_c": int, "source": str}
    if set(value) != set(required):
        fail("schema_error", "required and additional fields do not match")
    for key, expected_type in required.items():
        if not isinstance(value[key], expected_type):
            fail("schema_error", f"{key} has the wrong type")
    if not -80 <= value["temperature_c"] <= 80:
        fail("business_validation_error", "temperature is out of range")
    return value


def parse_tool_call(raw):
    if raw.get("type") != "function_call":
        fail("schema_error", "not a function call")
    if not raw.get("call_id") or not raw.get("name"):
        fail("schema_error", "call_id and name are required")
    if not isinstance(raw.get("arguments"), dict):
        fail("schema_error", "arguments must be an object")
    return {
        "status": "pending_approval",
        "call_id": raw["call_id"],
        "name": raw["name"],
        "arguments": copy.deepcopy(raw["arguments"]),
        "delay_ms": raw.get("delay_ms", 0),
    }


def validate_arguments(arguments):
    if set(arguments) != set(WEATHER_SCHEMA["required"]):
        fail("schema_error", "weather arguments must contain only city and units")
    for key, expected_type in WEATHER_SCHEMA["required"].items():
        if not isinstance(arguments[key], expected_type):
            fail("schema_error", f"{key} has the wrong type")
    if arguments["units"] not in WEATHER_SCHEMA["allowed_units"]:
        fail("schema_error", "units is not allowed")
    if arguments["city"] not in ALLOWED_CITIES:
        fail("policy_error", "city is outside the fixture resource scope")


def execute_weather(call, actor, deadline_ms=50):
    if call["name"] not in TOOL_REGISTRY:
        fail("permission_error", "tool is not allowlisted")
    if actor.get("scope") != TOOL_REGISTRY[call["name"]]["scope"]:
        fail("permission_error", "actor lacks the tool scope")
    validate_arguments(call["arguments"])
    if call.get("delay_ms", 0) > deadline_ms:
        fail("timeout_error", "tool exceeded the deadline")

    key = call["call_id"]
    args_fingerprint = json.dumps(call["arguments"], sort_keys=True)
    if key in EXECUTION_CACHE:
        old_fingerprint, old_result = EXECUTION_CACHE[key]
        if old_fingerprint != args_fingerprint:
            fail("conflict_error", "same call_id has different arguments")
        return {"status": "replayed", "result": old_result}

    result = {"city": call["arguments"]["city"], "temperature_c": 22}
    EXECUTION_CACHE[key] = (args_fingerprint, result)
    EXECUTION_LOG.append({"call_id": key, "tool": call["name"]})
    return {"status": "executed", "result": result}


def authorize_and_execute(raw_call, actor):
    pending = parse_tool_call(raw_call)
    return execute_weather(pending, actor)


def safe_call(raw_call, actor):
    try:
        return authorize_and_execute(raw_call, actor)
    except ValueError as error:
        code, _, detail = str(error).partition(":")
        return {"status": "rejected", "code": code, "detail": detail}


json_result = parse_json_output(MODEL_JSON_OUTPUT)
pending = parse_tool_call(MODEL_TOOL_OUTPUT)
actor = {"scope": "weather:read"}
first = safe_call(MODEL_TOOL_OUTPUT, actor)
duplicate = safe_call(MODEL_TOOL_OUTPUT, actor)
conflict_call = copy.deepcopy(MODEL_TOOL_OUTPUT)
conflict_call["arguments"]["city"] = "Beijing"
missing_call = copy.deepcopy(MODEL_TOOL_OUTPUT)
del missing_call["arguments"]["city"]
forbidden_call = copy.deepcopy(MODEL_TOOL_OUTPUT)
forbidden_call["arguments"]["city"] = "Secret Base"
unknown_tool = copy.deepcopy(MODEL_TOOL_OUTPUT)
unknown_tool["name"] = "delete_records"
timeout_call = copy.deepcopy(MODEL_TOOL_OUTPUT)
timeout_call["call_id"] = "weather_call_timeout"
timeout_call["delay_ms"] = 100

results = {
    "json": {"valid": True, "city": json_result["city"], "temperature_c": json_result["temperature_c"]},
    "tool": {
        "model_status": pending["status"],
        "first": first["status"],
        "duplicate": duplicate["status"],
        "execution_log_size": len(EXECUTION_LOG),
    },
    "rejections": {
        "conflict": safe_call(conflict_call, actor),
        "missing": safe_call(missing_call, actor),
        "forbidden_resource": safe_call(forbidden_call, actor),
        "unknown_tool": safe_call(unknown_tool, actor),
        "timeout": safe_call(timeout_call, actor),
    },
}

assert results["json"]["valid"] is True
assert results["tool"]["model_status"] == "pending_approval"
assert results["tool"]["first"] == "executed"
assert results["tool"]["duplicate"] == "replayed"
assert results["tool"]["execution_log_size"] == 1
assert results["rejections"]["conflict"]["code"] == "conflict_error"
assert results["rejections"]["missing"]["code"] == "schema_error"
assert results["rejections"]["forbidden_resource"]["code"] == "policy_error"
assert results["rejections"]["unknown_tool"]["code"] == "permission_error"
assert results["rejections"]["timeout"]["code"] == "timeout_error"

print(json.dumps(results, ensure_ascii=False, sort_keys=True))
```

### 观察输出

{% note success flat %}
预期输出会显示 JSON 通过语法、形状和范围校验；模型工具块先是 `pending_approval`，第一次通过权限和参数门禁后执行，重复调用只重放缓存结果，执行日志仍只有一条。缺字段、越权资源、未知工具、相同 ID 换参数和超时分别进入不同拒绝代码。这里的 `temperature_c=22` 是 fixture 值，不是线上天气结果。
{% endnote %}

```text
{"json": {"city": "Shanghai", "temperature_c": 22, "valid": true}, "rejections": {"conflict": {"code": "conflict_error", "detail": "same call_id has different arguments", "status": "rejected"}, "forbidden_resource": {"code": "policy_error", "detail": "city is outside the fixture resource scope", "status": "rejected"}, "missing": {"code": "schema_error", "detail": "weather arguments must contain only city and units", "status": "rejected"}, "timeout": {"code": "timeout_error", "detail": "tool exceeded the deadline", "status": "rejected"}, "unknown_tool": {"code": "permission_error", "detail": "tool is not allowlisted", "status": "rejected"}}, "tool": {"duplicate": "replayed", "execution_log_size": 1, "first": "executed", "model_status": "pending_approval"}}
```

## 副作用边界

### 授权边界

{% note warning flat %}
“模型选择了工具”与“应用允许工具执行”必须是两个状态。模型可能生成不存在的工具名、错误参数、越权资源或看似合理的重复调用；结构化输出只让这些情况更容易被程序发现，并不会替代权限、预算、确认和审计。
{% endnote %}

| 状态 | 模型可以做什么 | 应用必须做什么 |
| --- | --- | --- |
| 提议 | 输出工具名和参数 | 保存 raw block，标记 `pending_approval` |
| 解析 | 形成内部调用对象 | 严格校验 JSON、类型、枚举和额外字段 |
| 授权 | 无权自行提升权限 | 用 actor、租户、资源和动作做策略判断 |
| 执行 | 不能直接触发副作用 | 应用控制超时、幂等、重试和审计 |
| 回传 | 接收工具结果作为上下文 | 脱敏结果，保留调用 ID 和执行状态 |

对只读天气工具，自动执行的风险较低；对写操作应增加人类确认、一次性授权或更窄的权限 scope。不要因为一次工具调用成功，就默认下一次同名调用也可执行。

## 结果验证

### 验收证据

| 验收项 | 通过证据 | 失败信号 | 复测动作 |
| --- | --- | --- | --- |
| JSON 语法 | `json.loads` 成功 | 截断或自然语言包裹 JSON | 注入缺引号和 Markdown 前后缀 |
| JSON 形状 | 必需字段、类型和无额外字段 | 字段缺失或多出未定义字段 | 删除字段、改变类型、增加字段 |
| 工具参数 | 名称、调用 ID、参数 schema 通过 | 模型输出未知工具或缺字段 | 运行未知工具、缺城市、非法单位 |
| 权限 | actor scope 和资源范围通过 | 模型目标超出授权范围 | 使用未授权 scope 和受限城市 |
| 幂等 | 同 ID 同参数重放，日志不增加 | 重试导致重复执行 | 同参数重复调用，再用同 ID 换参数 |
| 截止时间 | 超时在副作用前拒绝 | 慢工具占用请求或半执行 | 将 fixture 延迟设为超过预算 |
| 回传 | 结果关联原调用 ID 且已脱敏 | 工具结果被当成新指令或串错调用 | 复验多调用顺序和错误结果 |

### 复测动作

1. 为每一个工具写参数 schema、允许 scope、资源范围、超时和幂等策略，不把它们藏在模型 Prompt 中。
2. 对模型正常输出、空输出、未知工具、缺字段、错误类型、越权资源和重复调用分别保留 fixture。
3. 将 parser、业务校验、授权和执行日志分开断言；只检查最终文本会漏掉工具状态和副作用。
4. 真实工具接入前先审计凭据、数据范围和副作用；本地 fixture 通过仅说明门禁逻辑可运行。

## 常见问题

{% flashcard basic id:llm-structured-output-business-validation deck:"大模型应用开发" priority:1 tags:"结构化输出与工具调用,Schema" %}
--- question
结构化输出为什么仍然需要业务校验？
--- answer
结构化输出主要约束可解析的形状，不能自动证明事实、权限、资源范围、数值关系或业务动作是正确且允许的。
--- explanation
可以按四层检查：

1. **语法**：字符串是否是合法 JSON，是否存在截断。
2. **Schema**：必需字段、类型、枚举和额外字段是否符合契约。
3. **业务语义**：数值范围、字段之间的关系、证据是否来自输入。
4. **策略权限**：目标资源、请求者、租户、预算和副作用是否允许。

即使 Provider 的 JSON Schema 或工具参数校验通过，`city="Secret Base"`、`amount=-1` 或 `action="delete_records"` 仍可能在业务层不允许。只有全部门禁通过，结果才能进入执行或下游状态变更。
{% endflashcard %}

{% flashcard basic id:llm-tool-call-execution-boundary deck:"大模型应用开发" priority:1 tags:"结构化输出与工具调用,工具安全" %}
--- question
工具调用和直接执行的边界是什么？
--- answer
模型只能提出带名称和参数的调用，应用必须先解析、校验 schema、检查权限、应用超时与幂等策略，再决定是否执行并记录审计。
--- explanation
推荐将流程保持为显式状态机：

`function_call → pending_approval → schema_validated → authorized → executed/replayed/rejected → tool_result`

其中：

- `function_call` 是模型输出，不是程序指令。
- `schema_validated` 只说明参数形状正确，不说明用户有权限。
- `authorized` 由应用策略决定，不能由 Prompt 或模型自称的角色授予。
- `executed` 必须受截止时间和幂等键约束；同一 ID 换参数应是冲突而不是新动作。
- `tool_result` 要关联原调用并脱敏，再作为下一轮上下文。

读操作也应保留这条边界；一旦工具可以写入、发送、退款或删除，就需要更严格的确认和审计机制。
{% endflashcard %}
