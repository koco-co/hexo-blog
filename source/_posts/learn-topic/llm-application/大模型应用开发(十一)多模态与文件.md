{% note primary flat %}
文件上传成功，只能证明资源进入了某个存储边界；它没有证明模型读懂了内容，也没有证明当前请求者有权读取。多模态输入还要区分内容块、文件引用、MIME、大小、权限、哈希和结果证据。本节用本地图片与文本文件 fixture 跑完这条链路。
{% endnote %}

<!-- concept-story:start -->
一个报销助手收到一张票据图片。上传接口返回了文件 ID，工程师便把模型返回的“总额 120”写入账本。第二天同一文件被另一个租户引用，模型看到了图片却没有对应的文本证据；文件删除后，缓存里的旧引用仍然能够被读取。

团队于是把文件当成有生命周期的资源，把多模态输入当成带类型的内容块，并要求 OCR 或视觉结论携带文件哈希和人工复核状态。上传、读取、解析和业务采纳不再是同一个成功条件。
<!-- concept-story:end -->

## 内容块

### 内容块、文件上传和引用

不同入口的外层字段不同，但都可以拆成四个概念：

| 概念 | 作用 | 需要保存的证据 | 常见误区 |
| --- | --- | --- | --- |
| 内容块 | 描述文本、图片、音频、视频或文档如何进入一次请求 | `type`、媒体类型、顺序和引用 | 把所有媒体压成字符串 |
| 文件资源 | 供一次或多次请求引用的对象 | file ID、租户、owner、大小、MIME、哈希和状态 | 只有 file ID，没有归属和删除记录 |
| 内容引用 | 将文件或内联数据绑定到消息 | 引用 ID/URL、权限、版本和过期时间 | 读取引用时跳过权限校验 |
| 结果证据 | 说明答案来自哪个文件或哪段内容 | 哈希、页码/区域、解析版本和置信度 | 把模型结论直接当事实 |

OpenAI Responses 的输入可以出现文本、图片和文件相关项目；Anthropic Messages 用不同的内容块和 `source` 形状承载图片/文档；Gemini `generateContent` 使用 `parts`、内联数据或文件数据，Interactions 又有自己的输入与执行步骤。统一层可以抽象 `text/image/audio/video/document`，但不能丢掉 Provider 原始块。

### 文件接口

| 接口方式 | 适合的场景 | 优点 | 风险与边界 |
| --- | --- | --- | --- |
| 内联 Base64/数据 URL | 小型、一次性媒体 | 请求自包含，容易绑定本次调用 | 请求变大、日志泄露、大小限制 |
| 外部 URL | 已有受控对象存储 | 请求体较小，可复用资源 | Provider 是否能访问、URL 是否过期、SSRF/越权 |
| Provider file ID | 多轮或多次引用 | 由 Provider 管理资源引用 | 存储期限、删除接口、跨项目权限要单独确认 |
| 应用资源 ID | 需要统一租户和删除策略 | 应用掌握授权与审计 | 仍须把资源转换成目标 Provider 支持的内容块 |

文件接口的选择不应只看上传速度。还要检查可接受的 MIME、最大大小、是否扫描恶意内容、是否允许模型训练/保存、引用有效期、删除语义和失败后缓存如何失效。

## 文件生命周期

### 生命周期与权限

文件资源至少经历以下状态：

```text
created
   │ MIME/大小/哈希/恶意内容检查
   ▼
validated ──权限通过──> referenced ──解析/模型处理──> evidenced
   │                         │                         │
   └──────────────删除/过期──┴─────────────────────────┘
                              ▼
                           deleted
```

| 阶段 | 门禁 | 失败结果 |
| --- | --- | --- |
| 创建 | 读取字节、声明 MIME、大小和租户 | `mime_error` / `size_error` |
| 校验 | 签名、哈希、编码、病毒扫描和文件版本 | `validation_error` |
| 引用 | actor、租户、用途和 Provider 能力 | `forbidden` / `unsupported` |
| 解析 | OCR/解析器输出、页码和版本 | `parse_error` |
| 采纳 | 结果证据、置信度和人工复核 | `needs_review` |
| 删除 | 本地对象、Provider 资源、缓存、索引和日志策略 | 不能只删除一张主表 |

删除后不能只让 UI 隐藏文件。应用还要使 file ID、下载 URL、Provider handle、派生 OCR、向量索引和输出缓存失效；审计日志可以保留必要的脱敏事件，但不应继续保留原始内容。

### 结果复核

OCR 与视觉模型输出都属于“带证据的候选结果”：

- OCR 结果要关联文件哈希、页码/区域、解析版本和置信度；低置信度或关键字段变更进入人工复核。
- 视觉模型的标签、金额、身份或合规判断不能只凭自然语言采纳；要保存原始内容块和可复核区域。
- 结构化 JSON 只保证形状时，业务层仍须检查数值范围、币种、字段关系和权限。
- 用户删除或撤回授权后，旧结果、缓存和索引都不能继续作为新事实使用。

## 结果校验

### 结果复核

{% note warning flat %}
“模型返回了字段”不等于“文件中存在该事实”。文件读取、内容解析、模型结论和业务采纳应有不同状态。对报销金额、合同条款、身份和安全告警等高风险字段，低置信度、哈希不匹配、缺少页码或权限变化都应转人工复核或拒绝采纳。
{% endnote %}

| 结果状态 | 含义 | 可进入下游吗 |
| --- | --- | --- |
| `parsed` | 字节和格式可解析 | 只能进入证据处理 |
| `evidenced` | 结果关联了文件哈希和区域/页码 | 可供业务规则继续校验 |
| `needs_review` | 置信度、冲突或风险超过自动阈值 | 不可自动写入关键业务状态 |
| `rejected` | MIME、权限、哈希或 schema 不通过 | 不可使用，可记录脱敏错误 |
| `deleted` | 原资源或授权已撤回 | 旧结果和缓存必须失效 |

## 最小实践

### 准备输入

{% note info flat %}
下面的 Python 代码使用 `TemporaryDirectory` 创建本地合成 PNG 和 UTF-8 文本文件，只读取内存/临时文件，不访问网络、不安装依赖、不调用模型。图片内容是固定的 1×1 PNG fixture，OCR/视觉结果也是合成结果；它只验证资源门禁和证据链，不证明模型的识别能力。
{% endnote %}

### 执行步骤

```python
import base64
import copy
import hashlib
import json
import tempfile
from pathlib import Path

PNG_BYTES = base64.b64decode(
    "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mNk+A8AAQUBAScY42YAAAAASUVORK5CYII="
)
TEXT_BYTES = "invoice_id=INV-001\ntotal=120\ncurrency=CNY\n".encode("utf-8")
MAX_BYTES = 256
STORE = {}


def fail(code, detail):
    raise ValueError(f"{code}:{detail}")


def detect_mime(name, data):
    if data.startswith(b"\x89PNG\r\n\x1a\n"):
        return "image/png"
    if name.endswith(".txt"):
        return "text/plain"
    return "application/octet-stream"


def scan_file(path, declared_mime):
    data = path.read_bytes()
    actual_mime = detect_mime(path.name, data)
    if actual_mime != declared_mime:
        fail("mime_error", f"declared={declared_mime},actual={actual_mime}")
    if len(data) > MAX_BYTES:
        fail("size_error", "file exceeds fixture limit")
    return {
        "mime": actual_mime,
        "size": len(data),
        "sha256": hashlib.sha256(data).hexdigest(),
        "path": path,
    }


def upload(file_id, path, tenant, owner, declared_mime):
    meta = scan_file(path, declared_mime)
    STORE[file_id] = {
        "tenant": tenant,
        "owner": owner,
        "deleted": False,
        "meta": meta,
    }
    return meta


def read_file(file_id, tenant, owner):
    record = STORE.get(file_id)
    if record is None or record["deleted"]:
        fail("not_found", file_id)
    if (record["tenant"], record["owner"]) != (tenant, owner):
        fail("forbidden", "file belongs to another principal")
    return record["meta"]


def delete_file(file_id, tenant, owner):
    record = STORE.get(file_id)
    if record is None:
        fail("not_found", file_id)
    if (record["tenant"], record["owner"]) != (tenant, owner):
        fail("forbidden", "only the owner can delete")
    record["deleted"] = True
    record["meta"] = {"sha256": record["meta"]["sha256"], "deleted": True}
    return "deleted"


def parse_text(meta):
    try:
        text = meta["path"].read_text(encoding="utf-8")
    except UnicodeDecodeError:
        fail("encoding_error", "text is not valid UTF-8")
    fields = dict(line.split("=", 1) for line in text.splitlines() if "=" in line)
    if set(fields) != {"invoice_id", "total", "currency"}:
        fail("parse_error", "required text fields are missing")
    if fields["currency"] != "CNY" or int(fields["total"]) <= 0:
        fail("business_validation_error", "invoice total or currency is invalid")
    return {"invoice_id": fields["invoice_id"], "total": int(fields["total"]), "currency": fields["currency"]}


def verify_claim(claim, meta, confidence_floor):
    if claim["evidence_hash"] != meta["sha256"]:
        fail("evidence_error", "claim is bound to another file")
    if not 0 <= claim["confidence"] <= 1:
        fail("schema_error", "confidence is outside [0, 1]")
    status = "evidenced" if claim["confidence"] >= confidence_floor else "needs_review"
    return {"status": status, "label": claim["label"], "confidence": claim["confidence"]}


def safe(action, *args):
    try:
        return action(*args)
    except ValueError as error:
        code, _, detail = str(error).partition(":")
        return {"status": "rejected", "code": code, "detail": detail}


with tempfile.TemporaryDirectory() as directory:
    root = Path(directory)
    image_path = root / "receipt.png"
    text_path = root / "receipt.txt"
    wrong_path = root / "wrong.txt"
    large_path = root / "large.txt"
    image_path.write_bytes(PNG_BYTES)
    text_path.write_bytes(TEXT_BYTES)
    wrong_path.write_bytes(PNG_BYTES)
    large_path.write_bytes(b"x" * (MAX_BYTES + 1))

    image_meta = upload("file_img_001", image_path, "tenant-a", "user-a", "image/png")
    text_meta = upload("file_txt_001", text_path, "tenant-a", "user-a", "text/plain")
    parsed_text = parse_text(text_meta)
    vision = verify_claim({
        "label": "receipt",
        "evidence_hash": image_meta["sha256"],
        "confidence": 0.72,
    }, image_meta, 0.90)
    ocr = verify_claim({
        "label": "invoice_total",
        "evidence_hash": text_meta["sha256"],
        "confidence": 0.98,
    }, text_meta, 0.90)

    before_delete = read_file("file_img_001", "tenant-a", "user-a")["mime"]
    cross_tenant = safe(read_file, "file_img_001", "tenant-b", "user-b")
    wrong_mime = safe(scan_file, wrong_path, "text/plain")
    oversized = safe(scan_file, large_path, "text/plain")
    bad_encoding_path = root / "bad.txt"
    bad_encoding_path.write_bytes(b"\xff\xfe")
    bad_encoding_meta = scan_file(bad_encoding_path, "text/plain")
    bad_encoding = safe(parse_text, bad_encoding_meta)
    delete_result = delete_file("file_img_001", "tenant-a", "user-a")
    after_delete = safe(read_file, "file_img_001", "tenant-a", "user-a")

    result = {
        "files": {
            "image": {"mime": image_meta["mime"], "size": image_meta["size"], "hash_prefix": image_meta["sha256"][:12]},
            "text": {"mime": text_meta["mime"], "size": text_meta["size"], "hash_prefix": text_meta["sha256"][:12], "parsed": parsed_text},
        },
        "claims": {"vision": vision, "ocr": ocr},
        "lifecycle": {"before_delete": before_delete, "delete": delete_result, "after_delete": after_delete["code"]},
        "errors": {
            "cross_tenant": cross_tenant["code"],
            "wrong_mime": wrong_mime["code"],
            "oversized": oversized["code"],
            "bad_encoding": bad_encoding["code"],
        },
    }

assert result["files"]["image"]["mime"] == "image/png"
assert result["files"]["text"]["parsed"]["total"] == 120
assert result["claims"] == {
    "vision": {"status": "needs_review", "label": "receipt", "confidence": 0.72},
    "ocr": {"status": "evidenced", "label": "invoice_total", "confidence": 0.98},
}
assert result["lifecycle"] == {"before_delete": "image/png", "delete": "deleted", "after_delete": "not_found"}
assert result["errors"] == {
    "cross_tenant": "forbidden", "wrong_mime": "mime_error",
    "oversized": "size_error", "bad_encoding": "encoding_error",
}

print(json.dumps(result, ensure_ascii=False, sort_keys=True))
```

### 观察输出

{% note success flat %}
预期输出应包含图片/文本的 MIME、大小、哈希前缀和文本解析结果；视觉结论因置信度 `0.72` 进入 `needs_review`，带文件哈希的高置信 OCR fixture 才进入 `evidenced`。跨租户读取、MIME 不匹配、超限和错误编码分别失败；删除后同一文件 ID 返回 `not_found`。这证明的是应用门禁与证据绑定，不是 OCR 或视觉模型的准确率。
{% endnote %}

```text
{"claims": {"ocr": {"confidence": 0.98, "label": "invoice_total", "status": "evidenced"}, "vision": {"confidence": 0.72, "label": "receipt", "status": "needs_review"}}, "errors": {"bad_encoding": "encoding_error", "cross_tenant": "forbidden", "oversized": "size_error", "wrong_mime": "mime_error"}, "files": {"image": {"hash_prefix": "431ced6916a2", "mime": "image/png", "size": 68}, "text": {"hash_prefix": "65ce658c6eec", "mime": "text/plain", "parsed": {"currency": "CNY", "invoice_id": "INV-001", "total": 120}, "size": 42}}, "lifecycle": {"after_delete": "not_found", "before_delete": "image/png", "delete": "deleted"}}
```

## 结果验证

### 结果复核

| 验收项 | 通过证据 | 失败信号 | 复测动作 |
| --- | --- | --- | --- |
| MIME | 文件签名与声明一致 | 只相信扩展名或请求头 | 用 PNG 内容声明为文本 |
| 大小 | 字节数在 Provider/应用上限内 | 上传成功后才发现超限 | 生成超过上限的 fixture |
| 哈希 | 结果证据绑定到本次文件字节 | 结果引用了另一文件 | 替换内容但复用旧 claim |
| 文本解析 | 编码、必需字段、数值和币种通过 | 文件可读但字段不完整 | 注入错误编码、缺字段和负数 |
| 视觉结果 | 内容块、模型结果、置信度和区域可追溯 | 把标签或金额直接写入账本 | 降低置信度或删掉证据哈希 |
| 权限 | tenant/owner 在引用、下载、删除时都校验 | file ID 可跨租户读取 | 用另一租户读取和删除 |
| 删除 | 原文、派生结果、缓存和 Provider 引用失效 | 主表删除但旧 URL 仍可读 | 删除后访问 file ID、缓存和索引 |
| 人工复核 | `needs_review` 不进入关键副作用 | 低置信度结果自动采纳 | 将阈值、字段风险和复核状态加入 fixture |

### 复测动作

1. 为每种媒体保存签名、MIME、大小、哈希、租户、用途、版本和过期时间；不要只保存模型输出。
2. 对 OpenAI、Anthropic、Gemini 和其他 Provider 分别记录内容块、文件引用、流式/异步处理和删除能力。
3. 对 OCR、视觉、表格和文档解析设置字段级验收；关键事实必须带证据位置和人工复核状态。
4. 删除或撤回授权时，使本地对象、远端资源、下载 URL、派生结果、缓存和索引一起失效。

## 常见问题

{% flashcard basic id:llm-file-upload-not-reading deck:"大模型应用开发" priority:1 tags:"多模态与文件,文件处理" %}
--- question
文件上传成功是否等于模型正确读取？
--- answer
不等于。上传只证明资源进入了某个边界；还要验证 MIME、大小、权限、内容解析、模型能力、结果证据和业务采纳。
--- explanation
至少区分以下状态：

1. **资源可用**：字节存在，签名、声明 MIME 和大小通过。
2. **引用可用**：当前请求者、租户、用途和 Provider 内容块均有权限。
3. **内容可解析**：编码、页码、图片/文档结构和解析版本通过。
4. **结果有证据**：OCR/视觉结果关联文件哈希、页码/区域、置信度和原始块。
5. **业务可采纳**：数值、字段关系、时效和人工复核策略通过。

任何一层失败，都不能用“有 file ID”替代。尤其是删除或撤回授权后，旧缓存和派生结果也必须失效。
{% endflashcard %}

{% flashcard basic id:llm-multimodal-evidence deck:"大模型应用开发" priority:1 tags:"多模态与文件,结果验证" %}
--- question
多模态结果如何保留证据？
--- answer
保存原始内容块或文件哈希、引用 ID、媒体类型、页码/区域、解析版本、模型版本、置信度和人工复核状态，并在权限变化或删除后使结果失效。
--- explanation
一条可复核结果至少要能回答：

- **看了什么**：文件 ID/哈希、内容块类型、顺序和媒体 MIME。
- **看到了哪里**：页码、区域、时间段或文本片段，而不是只保留一句结论。
- **谁看了**：租户、用户、用途和授权时点。
- **怎样得到**：解析器、模型/快照、Prompt 版本和结构化 schema。
- **能否采纳**：置信度、冲突、风险等级和人工复核决定。

哈希能证明结果绑定了哪份字节，但不能证明模型识别正确；因此高风险字段仍要做业务校验和人工复核。
{% endflashcard %}
