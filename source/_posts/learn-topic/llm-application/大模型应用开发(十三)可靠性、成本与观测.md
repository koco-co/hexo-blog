{% note primary flat %}
可靠性不是“平均请求很快”，成本不是“本月总账单可接受”，观测也不是“日志里有一句成功”。本节用本地调用记录器计算 p50/p95、Token、估算成本、错误率和质量信号，再验证显式降级、Trace 关联和脱敏边界。
{% endnote %}

<!-- concept-story:start -->
一个客服接口平均延迟只有 350 毫秒，团队据此把超时预算设成 500 毫秒。上线高峰时，最慢的 5% 请求接近 900 毫秒，用户看到的是超时和重试；降级逻辑又没有写明原因，报表把备用模型的结果算成了主模型成功。

排查者需要同时看到请求预算、每次尝试、Provider 状态、Token、成本、质量和 Trace。只有这样，团队才能判断是扩大预算、改变上下文、启用备用模型，还是拒绝继续降级，而不是用平均数和静默 fallback 掩盖问题。
<!-- concept-story:end -->

## 预算与降级

### 预算与重试

一次 LLM 请求至少有四种预算：

| 预算 | 约束对象 | 超出后的动作 |
| --- | --- | --- |
| 时间 | 总 deadline、连接 timeout、工具时间 | 取消当前尝试，检查是否还有降级预算 |
| 次数 | Provider 重试、fallback 尝试和工具重试 | 达到上限后返回明确失败 |
| Token | 输入、输出、工具和上下文 | 截断、摘要、换模型或拒绝 |
| 金额 | 单请求、用户、租户和日/月额度 | 停止扩张，转人工或低成本路径 |

重试和降级不是同义词：重试仍使用同一能力和请求语义，降级可能改变模型、上下文、质量或功能集合。两者都要记录 `attempt`、原因、剩余预算、结果和调用方可见的状态。

### 观测指标

| 指标 | 计算口径 | 不能掩盖的情况 |
| --- | --- | --- |
| 延迟 p50/p95 | 按请求或完整 Trace 的结束时间计算 | 平均值掩盖长尾和超时 |
| Token | 记录输入、输出、缓存/思考等 Provider 字段 | 只记总数无法定位 Context 成本 |
| 成本 | Token × 当前价格表，保留价格版本 | 价格变化和 fallback 成本被混合 |
| 错误率 | 明确定义分母和状态集合 | 把降级、取消、部分成功算作成功 |
| 质量 | schema、引用、任务指标或人工评分 | 只用 HTTP 200 当质量信号 |
| 降级率 | fallback 请求数 / 总请求数 | 静默换模型导致质量回归不可见 |

指标要带 `provider`、`model`、`prompt_version`、`tenant`（脱敏）、`route` 和 `trace_id` 等维度，但不要把原始 Prompt、凭据或完整用户输入作为高基数标签。日志和 Trace 可以保存受控摘要，原文按数据保留策略单独处理。

## 指标与Trace

### Trace关联

OpenTelemetry 将 Trace、Span、属性和事件作为可观测性基础；LLM 调用可以把一次用户请求作为 Trace，把 Context 装配、Provider 请求、工具调用和评估作为子 Span。关联字段至少包括：

- `trace_id`：贯穿一次用户请求和所有 attempt。
- `span_id`：区分 Context、Provider、工具和 fallback 阶段。
- `request_id`：Provider 返回或应用生成的请求关联值。
- `attempt`：区分重试与降级，不覆盖原始记录。
- `status`、`error.type`、`model`、`usage` 和成本价格版本。

Trace 关联不是把所有输入复制到每个 Span。应用可以记录 Prompt 版本、输入哈希前缀、Context 数量和引用 ID；需要排查原文时，通过受控存储和权限访问，而不是把敏感内容放进指标标签。

### 成本与质量

成本优化必须和质量回归一起评估：

| 优化动作 | 可能节省 | 质量/可靠性风险 | 必须对照的信号 |
| --- | --- | --- | --- |
| 缩短 Context | 输入 Token、延迟 | 丢规则、证据或历史 | 引用覆盖、拒答率、任务分数 |
| 换小模型 | 单 Token 成本、速度 | 结构化、工具或复杂任务失败 | schema 通过率、长尾和人工评分 |
| 增加缓存 | 重复请求成本 | 过期、越权或错误复用 | 键命中、数据版本和删除 |
| 增加重试 | 短暂错误恢复 | 延迟、费用和重复副作用 | attempt、deadline、幂等和 p95 |
| 启用 fallback | 可用性 | 能力下降、结果风格变化 | 降级率、质量差值和用户提示 |

成本计算应引用带日期/版本的价格表，并在记录中保留输入、输出、缓存命中和 fallback 的分项；估算值不能冒充账单。质量回归需要固定代表性输入和验收规则，不能因为新路径更便宜就删除失败样例。

## 生产边界

### 成本与质量

{% note warning flat %}
静默降级会把可靠性问题改写成质量问题，日志泄露会把观测系统变成新的数据出口，平均数会把长尾隐藏起来。任何预算、fallback 或成本优化都必须让调用方知道结果是否降级、使用了哪个模型、消耗了多少 Token，以及为何没有继续尝试。
{% endnote %}

生产策略至少应满足：

1. **显式**：返回 `primary`、`degraded`、`failed` 等状态，并记录原因。
2. **有界**：重试次数、fallback 次数、总时间和金额均有硬上限。
3. **可回滚**：Prompt、模型、价格表和降级策略有版本，变更可通过 feature flag 或配置回退。
4. **可复盘**：Trace 能从请求串到 Provider、工具、错误和最终结果。
5. **可脱敏**：日志默认不写 Prompt、Key、文件原文和完整工具参数；需要排查时使用受控摘要。
6. **可验证**：用固定 fixture 比较质量、成本、延迟和错误，不只看单次成功。

## 最小实践

### 准备输入

{% note info flat %}
下面的 Python 代码只处理五条本地合成调用记录，不访问网络、不读取环境变量、不包含真实凭据，也不连接 OpenTelemetry collector。价格是 fixture 内的微美元费率，质量分数是合成信号；代码只展示指标口径、预算和脱敏 Trace 的验证方式。
{% endnote %}

### 执行步骤

```python
import copy
import hashlib
import json
import math

PRICES_MICRO_USD_PER_1K = {
    "primary": {"input": 800, "output": 2400},
    "fallback": {"input": 400, "output": 1200},
}
CALLS = [
    {"trace_id": "trace_001", "span_id": "span_001", "request_id": "req_001", "attempt": 1,
     "model": "primary", "latency_ms": 100, "input_tokens": 100, "output_tokens": 20,
     "status": "ok", "quality": 0.94, "fallback_used": False, "fallback_reason": None,
     "prompt": "fixture customer text"},
    {"trace_id": "trace_002", "span_id": "span_002", "request_id": "req_002", "attempt": 1,
     "model": "primary", "latency_ms": 120, "input_tokens": 120, "output_tokens": 25,
     "status": "ok", "quality": 0.92, "fallback_used": False, "fallback_reason": None,
     "prompt": "fixture customer text"},
    {"trace_id": "trace_003", "span_id": "span_003", "request_id": "req_003", "attempt": 1,
     "model": "primary", "latency_ms": 130, "input_tokens": 110, "output_tokens": 30,
     "status": "ok", "quality": 0.91, "fallback_used": False, "fallback_reason": None,
     "prompt": "fixture customer text"},
    {"trace_id": "trace_004", "span_id": "span_004", "request_id": "req_004", "attempt": 2,
     "model": "fallback", "latency_ms": 500, "input_tokens": 90, "output_tokens": 20,
     "status": "degraded", "quality": 0.84, "fallback_used": True, "fallback_reason": "primary_timeout",
     "prompt": "fixture customer text"},
    {"trace_id": "trace_005", "span_id": "span_005", "request_id": "req_005", "attempt": 1,
     "model": "primary", "latency_ms": 900, "input_tokens": 200, "output_tokens": 40,
     "status": "error", "quality": None, "fallback_used": False, "fallback_reason": None,
     "prompt": "fixture customer text"},
]
BASELINE_QUALITY = 0.90
CANDIDATE_QUALITY = 0.78


def percentile(values, fraction):
    ordered = sorted(values)
    rank = max(0, math.ceil(fraction * len(ordered)) - 1)
    return ordered[rank]


def cost_micro_usd(call):
    price = PRICES_MICRO_USD_PER_1K[call["model"]]
    return (call["input_tokens"] * price["input"] + call["output_tokens"] * price["output"]) // 1000


def redact(value):
    if isinstance(value, dict):
        hidden = {}
        for key, item in value.items():
            if key in {"prompt", "authorization", "api_key", "content"}:
                hidden[key] = "[redacted]"
            else:
                hidden[key] = redact(item)
        return hidden
    if isinstance(value, list):
        return [redact(item) for item in value]
    return value


def validate_trace(call):
    required = {"trace_id", "span_id", "request_id", "attempt", "model", "status"}
    return required <= set(call) and call["attempt"] >= 1


def fallback_policy(call):
    if call["fallback_used"] and not call["fallback_reason"]:
        raise ValueError("policy_error:silent fallback")
    return "visible_degraded" if call["fallback_used"] else "primary"


def quality_gate(baseline, candidate, allowed_drop=0.05):
    delta = candidate - baseline
    return {"delta": round(delta, 2), "promotion": "allowed" if delta >= -allowed_drop else "blocked"}


def error_rate(calls):
    return sum(call["status"] == "error" for call in calls) / len(calls)


for call in CALLS:
    assert validate_trace(call)
    fallback_policy(call)

latencies = [call["latency_ms"] for call in CALLS]
metrics = {
    "calls": len(CALLS),
    "average_ms": sum(latencies) / len(latencies),
    "p50_ms": percentile(latencies, 0.50),
    "p95_ms": percentile(latencies, 0.95),
    "input_tokens": sum(call["input_tokens"] for call in CALLS),
    "output_tokens": sum(call["output_tokens"] for call in CALLS),
    "cost_micro_usd": sum(cost_micro_usd(call) for call in CALLS),
    "error_rate": error_rate(CALLS),
    "degraded_rate": sum(call["status"] == "degraded" for call in CALLS) / len(CALLS),
}
redacted = redact(CALLS[0])
trace_ok = all(validate_trace(call) for call in CALLS)
fallbacks_visible = all(fallback_policy(call) != "primary" for call in CALLS if call["fallback_used"])
quality = quality_gate(BASELINE_QUALITY, CANDIDATE_QUALITY)

silent = copy.deepcopy(CALLS[0])
silent["fallback_used"] = True
silent["fallback_reason"] = None
try:
    fallback_policy(silent)
except ValueError as error:
    silent_fallback_error = str(error).split(":", 1)[0]

assert metrics == {
    "calls": 5, "average_ms": 350.0, "p50_ms": 130, "p95_ms": 900,
    "input_tokens": 620, "output_tokens": 135, "cost_micro_usd": 760,
    "error_rate": 0.2, "degraded_rate": 0.2,
}
assert redacted["prompt"] == "[redacted]"
assert trace_ok is True
assert fallbacks_visible is True
assert quality == {"delta": -0.12, "promotion": "blocked"}
assert silent_fallback_error == "policy_error"

print(json.dumps({
    "metrics": metrics,
    "trace": {"valid": trace_ok, "fallback_visible": fallbacks_visible, "redacted_prompt": redacted["prompt"]},
    "quality_gate": quality,
    "failures": {"silent_fallback": silent_fallback_error, "p95_over_500ms": metrics["p95_ms"] > 500},
}, ensure_ascii=False, sort_keys=True))
```

### 观察输出

{% note success flat %}
预期输出应明确显示平均延迟 350 毫秒但 p95 为 900 毫秒；五条记录的错误率和降级率分别为 0.2，Token 与微美元成本可以按模型费率复算。Trace 字段完整、Prompt 被脱敏，fallback 有可见原因；候选质量从 0.90 降到 0.78，质量门禁阻止发布，静默 fallback 进入策略错误。
{% endnote %}


## 结果验证

### 验收证据

| 验收项 | 通过证据 | 失败信号 | 复测动作 |
| --- | --- | --- | --- |
| 延迟 | 同时记录平均、p50、p95 和总 deadline | 只报平均数 | 加入一个长尾请求，检查 p95/SLO |
| Usage | 输入、输出和 Provider 扩展 Token 分项记录 | 只保存总 Token | 加入缓存/思考/工具 Token 字段 |
| 成本 | 价格表版本、模型、Token 和分项金额可复算 | 估算值冒充账单 | 修改费率和模型，重算成本 |
| 错误 | 分母、错误类型、取消和降级状态明确 | HTTP 200 就计成功 | 注入 4xx、429、5xx、超时和取消 |
| 降级 | fallback 原因、模型、质量和用户状态可见 | 静默换模型 | 清空 fallback reason 并断言策略错误 |
| Trace | trace/span/request/attempt 可串联 | 重试覆盖原记录 | 增加多 attempt 并核对关联 |
| 脱敏 | Prompt、Key 和原文不进入指标/日志 | 复制完整输入到 Span | 对嵌套字段和错误路径做扫描 |
| 质量 | 固定样例、schema、引用或人工信号可比较 | 只以成本/可用性发布 | 候选模型质量下降时阻止 promotion |

### 复测动作

1. 先定义指标分母、状态枚举、Token/价格口径和 Trace 边界，再接入采集器。
2. 用固定 fixture 注入长尾、错误、重试、fallback、取消和质量回归，检查指标是否仍可解释。
3. 将日志、Trace、指标和账单对照；估算成本与供应商账单不一致时保留两套口径。
4. 任何 Prompt、Context、模型、价格或降级策略变化都要带版本并重新评估，不用平均成功率覆盖 p95 和质量下降。

## 常见问题

{% flashcard basic id:llm-p95-vs-average deck:"大模型应用开发" priority:1 tags:"可靠性、成本与观测,延迟" %}
--- question
p95 比平均延迟多说明什么？
--- answer
p95 展示最慢约 5% 请求的尾部体验；它能暴露平均数掩盖的超时、排队、重试和长上下文问题，但仍要结合样本量与请求分组解释。
--- explanation
平均值把所有请求压成一个数，少量极慢请求可能被大量快速请求稀释。p95 取排序后靠近尾部的位置：

- 如果平均 350 毫秒、p95 900 毫秒，说明大多数请求不慢，但尾部已经可能违反用户 deadline。
- p95 还要按 Provider、模型、路由、Context 大小、工具和租户分组，否则不同负载会相互抵消。
- p95 不是单次最大值，也不能替代 p99、超时率和取消率；选择哪个分位点要与 SLO 和样本量对应。

一旦 p95 超过预算，应先定位 Context、队列、Provider、工具、重试或 fallback 阶段，再决定优化，而不是只把平均数写进报表。
{% endflashcard %}

{% flashcard basic id:llm-fallback-visible-quality deck:"大模型应用开发" priority:1 tags:"可靠性、成本与观测,降级" %}
--- question
降级策略如何避免静默降低质量？
--- answer
让 fallback 的触发原因、模型、能力变化、质量信号和用户可见状态都进入记录，并用固定评估阻止质量下降超过阈值的路径发布。
--- explanation
安全降级至少要有五个可观察字段：

1. `fallback_used`：本次是否离开主路径。
2. `fallback_reason`：超时、限流、不可用还是预算耗尽。
3. `model` 与能力集合：是否改变工具、结构化、多模态或上下文能力。
4. `quality`：schema、引用覆盖、任务指标或人工评分是否下降。
5. `attempt` 与预算：还重试了几次、消耗多少时间和金额。

应用可以向用户返回“已使用备用路径”或等价状态，但不要泄露内部凭据和策略细节。若候选质量低于基线阈值，应阻止 promotion、转人工或返回明确失败；只有成本下降而没有质量证据，不能称为成功优化。
{% endflashcard %}
