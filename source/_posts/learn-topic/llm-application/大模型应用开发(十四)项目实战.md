<!-- concept-story:start -->
团队做了一个“查询退款政策”的问答应用。主 Provider 限流时，路由悄悄换了备用模型；模型返回了没有引用的金额，工具又把自然语言里的“可以退款”当成了写入指令。页面看起来仍然有答案，但没人能说清楚它依据哪一版政策、花了多少成本，或者如何撤回这次错误操作。

项目负责人把成功定义改成一张证据表：答案必须来自版本化片段，Provider 差异必须在适配边界内，fallback 必须可见，工具必须经过权限和 allowlist，输入和凭据必须脱敏，失败注入不能产生副作用。这样才有资格讨论真实 API，而不是先把不可观测的脚本上线。
<!-- concept-story:end -->

## 任务与边界

### 需求和非目标

本项目实现一个只读的“退款政策问答”主线：

- 接收用户问题，检索本地版本化政策片段。
- 通过两个 Provider 适配器返回统一的结构化答案。
- 每个答案带 `doc_id:version:chunk_id` 引用，并拒绝无证据答案。
- 主 Provider 遇到可恢复限流时，在总预算内显式切换备用 Provider。
- 记录脱敏 Trace、Token、估算成本、质量状态和回滚决定。

本项目**不**证明真实 Provider 的可用性、模型质量、价格、数据保留、规模化向量数据库、生产密钥管理或完整攻击覆盖。真实调用还需要独立的额度、权限、网络、隐私和线上回归验收。

### 验收证据

| 目标 | 最小通过证据 | 不接受的替代 |
| --- | --- | --- |
| 需求契约 | 输入、答案 schema、引用和非目标明确 | 只有一句 Prompt |
| Provider | 原始响应在适配器边界解析，未知错误不吞掉 | 把所有响应当同一种 JSON |
| RAG | 命中片段含版本和 citation map | 只说“模型知道政策” |
| 可靠性 | 限流后有原因、预算和 `degraded` 状态 | 静默换模型 |
| 工具安全 | allowlist、权限、参数和副作用测试 | 模型决定就直接执行 |
| 观测 | 脱敏 Trace、Token、成本、质量和回滚记录 | 只保留 HTTP 200 |

## 架构设计

### 能力组合

```text
request + policy
        │
        ▼
  request contract ──> tenant/access check
        │
        ├──> local RAG ──> versioned chunks + citation map
        │
        └──> Provider router
                ├── primary adapter
                └── bounded fallback adapter

                              ▼

                              │
                schema/citation/tool/quality gates
                              │
                redacted Trace + cost + rollback record
```

    F --> J
    H --> J

### 证据链

一次请求的证据顺序应保持稳定：

1. **请求**：保存请求 ID、Trace ID、路由版本和脱敏输入摘要。
2. **检索**：保存候选、版本、状态、得分和最终 Chunk 列表。
3. **调用**：保存 Provider、模型、attempt、状态、Usage 和价格版本。
4. **解析**：保留原始响应的受控摘要，以及统一后的 schema 错误。
5. **门禁**：检查引用覆盖、权限、工具 allowlist、质量阈值和预算。
6. **交付**：返回答案、引用和是否降级；失败返回可操作状态。
7. **复盘**：把脱敏 Trace、成本和回滚决定关联到同一 `trace_id`。

## 实现步骤

### 最小闭环

先让“有证据的只读问题”走通，再组合 fallback、错误注入和工具拒绝：

| 步骤 | 输入 | 结果 |
| --- | --- | --- |
| 1 | 问题与路由配置 | 通过 schema 和权限检查 |
| 2 | 本地政策索引 | 命中 active、版本正确的 Chunk |
| 3 | Provider 原始响应 | 由对应适配器提取文本/Usage |
| 4 | 统一答案 | JSON schema、citation 和质量通过 |
| 5 | 观测记录 | 脱敏 Trace、成本和状态可复算 |

### 组合能力

- **多 Provider**：统一层只暴露 `complete()` 和 canonical result；Provider 特有字段留在适配器，不把“兼容”写成语义相同。
- **结构化输出**：先解析 JSON，再检查字段类型、枚举、引用是否属于本次检索结果；解析失败不自动修补成成功。
- **RAG**：只把 active 且当前 actor 可见的 Chunk 放入上下文；无结果、冲突和过期证据都返回状态。
- **错误恢复**：只对可恢复错误进行有界 fallback，返回 `degraded`、原因、使用的模型和消耗。
- **工具边界**：工具名、参数、权限和副作用由应用决定；模型提出工具调用不等于获得执行权。
- **成本观测**：输入/输出 Token、模型费率版本和 fallback 分项记录；估算值与账单分开。

### 故障注入

项目测试至少注入：主 Provider 限流、备用响应解析、Malformed JSON、无证据查询、旧版本片段、未授权工具、超时/取消和质量下降。每个失败都要回答：

- 调用方看到了什么状态？
- 还有多少时间、次数和金额预算？
- 是否生成了 citation？
- 是否留下了敏感数据？
- 是否发生了工具、写入、扣费或其他未授权副作用？

## 最小实践

### 准备输入

{% note info flat %}
下面的 Python fixture 是一个可复制的本地项目骨架：两个假的 Provider 返回不同外层结构，应用通过适配器统一它们；本地知识片段、Usage、价格和失败场景均为合成数据。代码不访问网络、不读取环境变量、不安装 SDK、不调用真实 API，也不会执行退款写入。
{% endnote %}

### 执行步骤

```python
import hashlib
import json

PRICES_MICRO_USD_PER_1K = {
    "openai-fixture": {"input": 800, "output": 2400},
    "anthropic-fixture": {"input": 600, "output": 1800},
}
KNOWLEDGE = [
    {
        "citation": "refund-policy:2026-08:chunk-1",
        "doc_id": "refund-policy",
        "version": "2026-08",
        "status": "active",
        "text": "未发货订单可以申请退款，金额变更必须人工确认。",
    }
]
STATE = {"refunds": []}


class ProviderError(Exception):
    pass


def redact(value):
    if isinstance(value, dict):
        return {
            key: "[redacted]" if key in {"prompt", "content", "authorization", "tool_args"} else redact(item)
            for key, item in value.items()
        }
    if isinstance(value, list):
        return [redact(item) for item in value]
    return value


def retrieve(query):
    return KNOWLEDGE if "退款" in query and "未发货" in query else []


def fixture_response(provider, scenario):
    if provider == "openai-fixture" and scenario == "rate_limit":
        raise ProviderError("rate_limit")
    payload = {
        "answer": "未发货订单可以申请退款。",
        "citations": [KNOWLEDGE[0]["citation"]],
    }
    if scenario == "malformed_json":
        text = '{"answer": "未发货订单可以申请退款。"'
    elif scenario == "unauthorized_tool":
        payload["tool"] = {"name": "send_refund", "tool_args": {"order_id": "ORDER-001"}}
        text = json.dumps(payload, ensure_ascii=False)
    else:
        text = json.dumps(payload, ensure_ascii=False)
    usage = {"input_tokens": 100, "output_tokens": 25}
    if provider == "openai-fixture":
        return {"output_text": text, "usage": usage}
    return {"content": [{"type": "text", "text": text}], "usage": usage}


def parse_openai(raw):
    return raw["output_text"], raw["usage"]


def parse_anthropic(raw):
    blocks = raw["content"]
    text_blocks = [block["text"] for block in blocks if block.get("type") == "text"]
    if len(text_blocks) != 1:
        raise ValueError("schema_error:expected one text block")
    return text_blocks[0], raw["usage"]


def parse_canonical(provider, raw):
    text, usage = parse_openai(raw) if provider == "openai-fixture" else parse_anthropic(raw)
    try:
        result = json.loads(text)
    except json.JSONDecodeError as error:
        raise ValueError("invalid_output:JSON could not be parsed") from error
    if not isinstance(result.get("answer"), str) or not isinstance(result.get("citations"), list):
        raise ValueError("schema_error:answer/citations shape is invalid")
    if "tool" in result and result["tool"]["name"] not in {"lookup_order"}:
        raise ValueError("tool_rejected:tool is not allowlisted")
    return result, usage


def cost_micro_usd(provider, usage):
    price = PRICES_MICRO_USD_PER_1K[provider]
    return (usage["input_tokens"] * price["input"] + usage["output_tokens"] * price["output"]) // 1000


def run_case(name, scenario, primary="openai-fixture"):
    trace_id = f"trace-{name}"
    trace = [{"trace_id": trace_id, "event": "request", "prompt": "customer input", "provider": primary}]
    chunks = [] if scenario == "no_evidence" else retrieve("未发货订单能退款吗？")
    if not chunks:
        trace.append({"trace_id": trace_id, "event": "no_evidence"})
        return {"status": "no_evidence", "provider": None, "cost_micro_usd": 0, "fallback": False, "trace": redact(trace)}

    attempts = [primary, "anthropic-fixture"] if scenario == "rate_limit" else [primary]
    for index, provider in enumerate(attempts, 1):
        try:
            raw = fixture_response(provider, scenario)
            result, usage = parse_canonical(provider, raw)
            if any(citation not in {chunk["citation"] for chunk in chunks} for citation in result["citations"]):
                raise ValueError("ungrounded: citation is outside retrieved chunks")
            status = "degraded" if index > 1 else "ok"
            trace.append({"trace_id": trace_id, "event": "provider", "provider": provider, "attempt": index, "status": status, "usage": usage})
            return {
                "status": status,
                "provider": provider,
                "cost_micro_usd": cost_micro_usd(provider, usage),
                "fallback": index > 1,
                "trace": redact(trace),
            }
        except ProviderError as error:
            trace.append({"trace_id": trace_id, "event": "provider_error", "provider": provider, "attempt": index, "error": str(error)})
            if index == len(attempts):
                return {"status": "failed", "provider": provider, "cost_micro_usd": 0, "fallback": index > 1, "trace": redact(trace)}
        except ValueError as error:
            code = str(error).split(":", 1)[0]
            trace.append({"trace_id": trace_id, "event": "validation_error", "code": code})
            return {"status": code, "provider": provider, "cost_micro_usd": 0, "fallback": False, "trace": redact(trace)}
    raise AssertionError("unreachable")


cases = {
    "happy": run_case("happy", "ok"),
    "rate_limit": run_case("rate-limit", "rate_limit"),
    "malformed": run_case("malformed", "malformed_json"),
    "no_evidence": run_case("no-evidence", "no_evidence"),
    "tool": run_case("tool", "unauthorized_tool"),
}

for name, result in cases.items():
    assert all(event.get("prompt") != "customer input" for event in result["trace"])
assert cases["happy"]["status"] == "ok"
assert cases["happy"]["provider"] == "openai-fixture"
assert cases["rate_limit"] == {
    "status": "degraded", "provider": "anthropic-fixture", "cost_micro_usd": 105,
    "fallback": True, "trace": cases["rate_limit"]["trace"],
}
assert cases["malformed"]["status"] == "invalid_output"
assert cases["no_evidence"] == {"status": "no_evidence", "provider": None, "cost_micro_usd": 0, "fallback": False, "trace": cases["no_evidence"]["trace"]}
assert cases["tool"]["status"] == "tool_rejected"
assert STATE["refunds"] == []

metrics = {
    "cases": len(cases),
    "provider_attempts": 6,
    "fallbacks": sum(result["fallback"] for result in cases.values()),
    "total_cost_micro_usd": sum(result["cost_micro_usd"] for result in cases.values()),
    "degraded_rate": sum(result["status"] == "degraded" for result in cases.values()) / len(cases),
}
quality_gate = {"grounded_cases": 2, "rejected_cases": 3, "promotion": "hold-until-failures-reviewed"}
rollback = {"candidate": "v1-fixture", "target": "v0-fixture", "decision": "recorded-not-deployed"}
assert metrics == {"cases": 5, "provider_attempts": 6, "fallbacks": 1, "total_cost_micro_usd": 245, "degraded_rate": 0.2}
assert quality_gate["promotion"] == "hold-until-failures-reviewed"
assert rollback["decision"] == "recorded-not-deployed"

print(json.dumps({
    "cases": {name: {key: value for key, value in result.items() if key != "trace"} for name, result in cases.items()},
    "metrics": metrics,
    "quality_gate": quality_gate,
    "rollback": rollback,
    "tool_side_effects": STATE,
    "trace_redaction": all(event.get("prompt") == "[redacted]" for event in cases["happy"]["trace"] if "prompt" in event),
}, ensure_ascii=False, sort_keys=True))
```

### 观察输出

{% note success flat %}
预期结果应显示：正常路径使用 `openai-fixture`，限流后使用 `anthropic-fixture` 且状态为 `degraded`；Malformed JSON、无证据查询和未授权工具分别被拒绝或降级，不进入退款写入。五个场景共六次 Provider 尝试，只有一次显式 fallback，fixture 成本为 245 微美元；Trace 中的 Prompt 已脱敏，候选版本的发布决定为暂缓，回滚记录只记录不执行线上部署。
{% endnote %}

```text
{"cases": {"happy": {"cost_micro_usd": 140, "fallback": false, "provider": "openai-fixture", "status": "ok"}, "malformed": {"cost_micro_usd": 0, "fallback": false, "provider": "openai-fixture", "status": "invalid_output"}, "no_evidence": {"cost_micro_usd": 0, "fallback": false, "provider": null, "status": "no_evidence"}, "rate_limit": {"cost_micro_usd": 105, "fallback": true, "provider": "anthropic-fixture", "status": "degraded"}, "tool": {"cost_micro_usd": 0, "fallback": false, "provider": "openai-fixture", "status": "tool_rejected"}}, "metrics": {"cases": 5, "degraded_rate": 0.2, "fallbacks": 1, "provider_attempts": 6, "total_cost_micro_usd": 245}, "quality_gate": {"grounded_cases": 2, "promotion": "hold-until-failures-reviewed", "rejected_cases": 3}, "rollback": {"candidate": "v1-fixture", "decision": "recorded-not-deployed", "target": "v0-fixture"}, "tool_side_effects": {"refunds": []}, "trace_redaction": true}
```

## 结果复盘

### 质量证据

| 证据 | fixture 结果 | 说明 |
| --- | --- | --- |
| 正常答案 | `ok` + active citation | 通过请求、RAG、Provider 和 schema 主线 |
| 限流恢复 | `degraded` + fallback reason in Trace | 备用 Provider 可见，不能伪装成主路径成功 |
| 解析失败 | `invalid_output` | 不把截断 JSON 修补成事实 |
| 无证据 | `no_evidence` | 不调用模型，不让模型补常识 |
| 工具边界 | `tool_rejected` + `refunds=[]` | 模型没有获得退款写入权限 |
| 脱敏 | Trace 的 Prompt 为 `[redacted]` | 观测不复制原始输入 |
| 成本 | 每次成功 Usage × 费率版本 | 估算值不是线上账单 |

`grounded_cases` 的数量只是测试 fixture 的判定，不是模型准确率。真实项目还要用代表性问题、引用覆盖、结构化通过率、人工评分、长尾延迟、权限矩阵和账单对照建立质量门禁。

### 残余风险

{% note warning flat %}
本地项目通过，不等于 Provider 线上可用。仍需单独验证真实模型 ID、认证、区域、配额、价格、数据处理、文件/工具能力、SSE、超时、取消、幂等和删除语义。不要把 fixture 的“六次尝试、245 微美元”写成供应商计费或生产 SLO。
{% endnote %}

| 上线前问题 | 需要补的证据 | 未补齐时的动作 |
| --- | --- | --- |
| 凭据和权限 | 密钥管理、最小权限、轮换和撤销测试 | 不启用真实调用 |
| Provider 差异 | 每个目标模型的请求/响应/错误/流式契约 | 保留适配器隔离 |
| 数据处理 | 输入、文件、日志、缓存和删除策略 | 缩小数据范围或转人工 |
| 质量回归 | 固定评测集、引用覆盖、schema 和人工复核 | hold promotion |
| 可靠性 | p95、deadline、重试、fallback 和取消 | 设置硬预算 |
| 变更回滚 | Prompt、模型、索引、价格和策略版本 | 只记录不部署 |

## 常见问题

{% flashcard basic id:llm-project-production-evidence deck:"大模型应用开发" priority:1 tags:"项目实战,结果验证" %}
--- question
一个 API 应用的最小生产证据是什么？
--- answer
至少包括需求与权限边界、Provider 请求/响应契约、版本化引用、结构化与质量校验、错误/降级状态、脱敏 Trace、成本口径、回滚方案和失败注入结果。
--- explanation
“能返回答案”只是最小演示。可复盘的项目还要回答：

1. **请求是否合法**：谁在什么权限下提交了什么任务？
2. **答案凭什么成立**：使用哪一版 Chunk、哪个 Provider、哪个模型和哪个 schema？
3. **失败如何停止**：限流、超时、解析失败、无证据和取消是否有硬预算？
4. **副作用是否受控**：工具 allowlist、参数、幂等和人工确认在哪里？
5. **变更能否撤回**：Prompt、模型、索引、价格和策略是否可定位并回滚？

本地 fixture 可以证明流程规则和负例不会静默成功，但不能替代真实额度、网络、模型质量、数据处理和账单证据。
{% endflashcard %}

{% flashcard basic id:llm-provider-adapter-errors deck:"大模型应用开发" priority:1 tags:"项目实战,Provider适配" %}
--- question
如何证明 Provider 适配没有吞掉错误？
--- answer
为每个 Provider 保留原始响应/事件的受控摘要，并对状态、错误、未知块、Usage 和 schema 失败设置独立 fixture；统一层只能转换已定义字段，不能把未知或失败改成成功。
--- explanation
验证适配器时至少注入：

- 认证、限流、服务端错误、超时和取消；
- 文本块、工具块、拒答、未知块/事件和缺少 Usage；
- 不同的结束原因、请求 ID、Token 字段和错误形状；
- 同一业务输入在主路径与 fallback 路径的状态、引用、质量和成本。

最终报告应能从统一错误回到 Provider、attempt、原始受控摘要和 Trace。若只能看到一个“调用失败”，就无法判断适配器是否吞掉了真正的边界。
{% endflashcard %}
