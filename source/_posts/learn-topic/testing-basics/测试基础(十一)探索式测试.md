{% note info flat %}
探索式测试把学习、设计和执行放在同一段时间盒中，用问题和启发式主动寻找模型遗漏。它不是无计划乱点，也不是脚本回归的替代品；探索记录必须让另一位测试者知道走过哪里、看见什么和下一步为什么。
{% endnote %}

## 探索目标

{% note primary flat %}
先写章程：目标、范围、时间盒、数据、环境、风险和完成产物。脚本测试负责重复确认已知规则，探索负责在有限时间内学习未知行为，两者可以在同一轮互相补充。
{% endnote %}

## 启发式

| 启发式 | 对借阅系统的提问 | 适合发现 |
| --- | --- | --- |
| 错误推测 | 冻结会员、库存 0、重复点击会怎样 | 边界与负向路径 |
| 变化维度 | 换账号、时区、网络、返回路径 | 隐藏状态与依赖 |
| 一致性 | 页面、接口、库存和记录是否一致 | 数据错位 |
| 恢复性 | 断网、超时、刷新、重进能否继续 | 中断与补偿 |
| 可观察性 | 是否有足够提示、日志和 ID | 难以诊断的失败 |

![局部探索围绕一个功能区域逐步扩大问题空间](/img/learn-topic/testing-basics/exploratory-local.png "局部探索")
![全局探索沿用户旅程和关联功能寻找遗漏](/img/learn-topic/testing-basics/exploratory-tours.png "全局探索")

{% note warning flat %}
启发式是提问清单，不是缺陷结论。发现异常后仍要固定输入、状态、版本和复现步骤，确认是产品问题、环境问题还是需求未决。
{% endnote %}

## 探索执行

{% timeline 一次探索会话, blue %}
<!-- timeline 设定章程 -->
写目标、范围、时间盒和停止条件，准备合成账号与数据。
<!-- endtimeline -->
<!-- timeline 学习与设计 -->
先执行最小路径，记录新信息，再根据风险选择下一个动作。
<!-- endtimeline -->
<!-- timeline 观察与记录 -->
保存步骤、输入、结果、截图/日志位置和疑问，不依赖记忆补写。
<!-- endtimeline -->
<!-- timeline 收束 -->
整理缺陷、风险、未覆盖区域和可转为回归的检查。
<!-- endtimeline -->
{% endtimeline %}

![探索式测试会话中目标、时间盒、观察与结论的记录方式](/img/learn-topic/testing-basics/exploratory-session.png "探索会话记录")

{% note primary flat %}
一个 30 分钟借阅探索可以把 5 分钟用于环境检查、20 分钟用于冻结账户/库存/恢复路径、5 分钟用于整理证据。时间盒到点并不等于“没有问题”，而是按停止条件交付当前发现和下一步建议。
{% endnote %}

## 复盘与沉淀

| 观察 | 复盘问题 | 后续动作 |
| --- | --- | --- |
| 发现新状态 | 原有状态图缺了哪条边？ | 补状态/转换用例 |
| 发现重复缺陷 | 为什么脚本未覆盖？ | 加入回归候选并追踪规则 |
| 环境阻塞 | 需要什么隔离夹具？ | 建立数据或依赖替身 |
| 证据不足 | 其他人能复现吗？ | 补版本、输入、日志和清理 |

{% note success flat %}
探索产物的价值在于把未知变成可复用知识：缺陷进入缺陷流程，稳定检查进入回归集，尚未确定的行为进入需求澄清。不要把探索会话的点击数量当作覆盖率。
{% endnote %}

## 常见问题

{% flashcard basic id:testing-basics-a11-concept-1 deck:"测试基础" priority:1 tags:"探索式测试,记录" %}
--- question
探索式测试需要写文档吗？
--- answer
需要保留足以复盘的章程、步骤、输入、观察、证据和未决问题，但不要求事先写完所有脚本。
--- explanation
探索的设计会随学习结果变化，不能用固定用例阻止新问题；如果完全不记录，别人无法复现，发现也无法沉淀为回归。最小记录包括目标和时间盒、版本/环境、路径和数据、实际结果、证据位置、风险与下一步。记录可以轻量，但不能用“凭感觉测过”替代。
{% endflashcard %}

{% flashcard basic id:testing-basics-a11-concept-2 deck:"测试基础" priority:1 tags:"探索式测试,随机测试" %}
--- question
探索式测试和随机测试有什么区别？
--- answer
探索式测试有目标、启发式和时间盒，并根据学习调整动作；随机测试主要随机生成输入或动作，未必有可解释的覆盖与复盘。
--- explanation
随机输入可以发现崩溃或边界异常，但若没有固定种子、状态和结果判定，失败很难复现。探索者会围绕“冻结账户恢复”“库存守恒”等问题选择动作，并在发现新信息后调整路径。两者可以结合：随机生成数据后仍需记录种子、模型和证据，不能把随机点击数量当作风险覆盖。
{% endflashcard %}
