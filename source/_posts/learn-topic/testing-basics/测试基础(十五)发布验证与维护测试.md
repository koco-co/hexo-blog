{% note info flat %}
发布验证不是把所有旧用例机械重跑，而是根据变更影响、风险和发布策略选择证据。维护测试还要观察线上行为、数据迁移和回退路径；一条修复确认通过，不代表相关功能和历史数据都安全。
{% endnote %}

## 变更分析

{% note primary flat %}
先读变更说明、代码/配置差异、数据迁移和依赖，再画影响范围：直接修改的功能、共享组件、权限、接口、状态和报告。回归集合应能追溯到这些影响，而不是按“上次跑过的列表”决定。
{% endnote %}

| 变更 | 直接检查 | 关联回归 |
| --- | --- | --- |
| 借阅资格规则 | 有效/冻结/逾期边界 | 登录、库存、报告 |
| 数据表迁移 | 新旧数据读写 | 查询、备份、回滚 |
| 前端表单 | 输入、错误、可访问性 | 接口契约、不同设备 |
| 外部依赖版本 | 超时与错误映射 | 重试、降级、监控 |

## 冒烟与准出

{% note primary flat %}
冒烟是快速确认版本可安装、关键入口可达、核心依赖可用的最小集合，不是完整回归，也不等于发布批准。准出还要检查高风险用例、严重缺陷、数据迁移、回退和剩余风险。
{% endnote %}

- 安装/升级完成，版本和迁移标识正确；
- 登录、核心读写和关键权限路径可执行；
- 监控、日志、告警和回退开关可用；
- 失败结果能定位到构建、环境、数据或产品责任；
- 未执行范围和风险接受者已经记录。

## 安装与升级

{% timeline 升级验证闭环, blue %}
<!-- timeline 基线 -->
备份合成数据，记录旧版本、配置、迁移版本和可回退点。
<!-- endtimeline -->
<!-- timeline 升级 -->
执行安装/迁移，检查启动、数据结构和关键读写。
<!-- endtimeline -->
<!-- timeline 中断 -->
在隔离环境模拟中断、重复执行或依赖失败，确认状态可恢复。
<!-- endtimeline -->
<!-- timeline 回退 -->
执行批准的回退流程，比较数据、配置和用户可见行为。
<!-- endtimeline -->
{% endtimeline %}

{% note warning flat %}
回滚代码不一定能回滚数据：向前兼容迁移、已写入的新字段、外部消息和缓存可能仍然存在。回退验证必须先问数据不变量、迁移逆操作和外部副作用，不能只把版本号改回去。
{% endnote %}

## 发布策略

| 策略 | 暴露方式 | 适合的验证 |
| --- | --- | --- |
| 蓝绿 | 两套环境切换流量 | 切换、会话、数据一致性与回退 |
| 滚动 | 分批替换实例 | 版本混跑、兼容和容量 |
| 灰度 | 少量用户/区域先接收 | 指标、错误率、回退阈值 |
| 实验 | 按分组比较行为 | 统计口径、隔离和终止条件 |

{% note info flat %}
发布策略改变风险暴露顺序，不会自动减少测试责任。混合版本期间要验证接口和数据兼容；灰度要提前定义停止阈值；任何自动回退都必须有可观察指标和人工兜底。
{% endnote %}

## 维护反馈

{% note danger flat %}
线上反馈不是“用户自己测”。记录事件时间、版本、影响范围、脱敏请求 ID、指标和恢复动作；把可重复的行为转为回归候选，把一次性外部故障与产品缺陷分开分析。
{% endnote %}

## 常见问题

{% flashcard basic id:testing-basics-a15-concept-1 deck:"测试基础" priority:2 tags:"修复确认,回归" %}
--- question
修复确认和回归测试有什么区别？
--- answer
修复确认重跑原失败条件，验证问题消失；回归测试检查变更影响的相关行为没有被破坏。
--- explanation
冻结账户仍可登录的修复确认只重跑冻结账户、正确密码和会话检查；回归还应覆盖正常登录、错误密码、解锁、权限和共享认证组件。回归范围由影响分析决定，不一定是全量，也不能只看页面提示。两者都要记录版本、数据和实际结果。
{% endflashcard %}

{% flashcard basic id:testing-basics-a15-concept-2 deck:"测试基础" priority:2 tags:"冒烟,准出" %}
--- question
冒烟测试通过能否直接发布？
--- answer
不能。冒烟只说明最小入口和依赖可用，发布还需满足高风险准出条件并处理严重缺陷、迁移、回退和剩余风险。
--- explanation
核心入口可打开并不代表支付超时、权限隔离或数据恢复正确。冒烟失败通常阻塞后续回归；冒烟通过后仍需按变更影响执行针对性回归，并给出未测范围和责任人。若业务明确把冒烟作为准入门槛，也不能把它升级成“没有缺陷”的保证。
{% endflashcard %}

{% flashcard basic id:testing-basics-a15-concept-3 deck:"测试基础" priority:2 tags:"回滚,数据迁移" %}
--- question
为什么回滚代码可能恢复不了数据？
--- answer
数据迁移、外部副作用、缓存和新旧版本写入可能不可逆；回滚必须验证数据不变量与兼容策略，而不只是切换代码版本。
--- explanation
新版本可能写入旧版本不认识的字段，消息已经发给外部系统，或迁移删除了旧数据。回退方案应包含备份/恢复、双写或兼容读取、缓存清理、未完成任务处理和恢复后核对。演练要在隔离环境进行，并记录可接受的数据损失和恢复时间。
{% endflashcard %}
