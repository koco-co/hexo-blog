{% note info flat %}
发布验证不是把所有旧用例机械重跑，而是根据变更影响、风险和发布策略选择证据。维护测试还要观察线上行为、数据迁移和回退路径；一条修复确认通过，不代表相关功能和历史数据都安全。
{% endnote %}

## 变更分析

### 影响范围

{% note primary flat %}
先读变更说明、代码/配置差异、数据迁移和依赖，再画影响范围：直接修改的功能、共享组件、权限、接口、状态和报告。回归集合应能追溯到这些影响，而不是按“上次跑过的列表”决定。
{% endnote %}

| 变更 | 直接检查 | 关联回归 |
| --- | --- | --- |
| 借阅资格规则 | 有效/冻结/逾期边界 | 登录、库存、报告 |
| 数据表迁移 | 新旧数据读写 | 查询、备份、回滚 |
| 前端表单 | 输入、错误、可访问性 | 接口契约、不同设备 |
| 外部依赖版本 | 超时与错误映射 | 重试、降级、监控 |

### 回归选择

| 影响判断 | 必做回归 | 选择理由 |
| --- | --- | --- |
| 资格/权限逻辑变化 | 正常、拒绝、边界和跨入口权限 | 防止修复一条路径后其他入口绕过 |
| 数据/迁移变化 | 读写、历史数据、升级后新建和回退 | 检查旧数据可用与不变量 |
| 共享组件变化 | 直接功能 + 关键用户旅程 | 共享代码的间接影响不能只跑单元 |

| Case | 变更触发 | 前置与步骤 | 可判定预期 | 纸面实际/结论（合成示例） | 证据链 |
| --- | --- | --- | --- | --- | --- |
| R15-01 | 借阅资格规则 | `M1` 启用、`M2` 冻结、`B1` 有库存；分别提交借阅 | M1 成功；M2 拒绝且库存/记录不变 | M2 若返回成功，结论 `FAIL`，建缺陷 D-1501 | 请求 ID、前后库存、记录快照 |
| R15-02 | 数据表迁移 | 备份旧数据；在写入阶段中断一次；重跑迁移并读写历史记录 | 重跑幂等、旧数据可读、版本只前进一次 | 合成夹具观察版本保持 2、记录数不变，结论 `PASS` | 迁移日志、版本号、前后计数 |
| R15-03 | 安装/卸载流程 | 安装 v2→取消安装；再安装→卸载；检查配置和用户数据 | 取消不留下半安装；卸载按约定清理或保留数据 | 合成夹具观察半安装目录被清理、保留项可读，结论 `PASS` | 安装日志、目录清单、数据快照 |
| R15-04 | 回退与外部依赖 | v2 写入新字段后回退 v1；重复执行回退并检查缓存/消息 | 代码可启动，数据不变量保持，外部副作用有补偿 | 合成夹具观察新字段残留导致 v1 读取失败，结论 `FAIL`，转数据迁移专项 | 回退时间线、字段对账、缓存/消息 ID |

{% note warning flat %}
表中“纸面实际/结论”是可复核的合成演练，用来示范怎样把输入、预期和观察结果串起来，不是某个线上系统已经执行的证据。真正发布前必须用候选版本替换合成结果，并保留首失败、重试、回退和清理记录；未执行项不能写成通过。
{% endnote %}

## 冒烟与准出

### 快速检查

{% note primary flat %}
冒烟是快速确认版本可安装、关键入口可达、核心依赖可用的最小集合，不是完整回归，也不等于发布批准。准出还要检查高风险用例、严重缺陷、数据迁移、回退和剩余风险。
{% endnote %}

- 安装/升级完成，版本和迁移标识正确；
- 登录、核心读写和关键权限路径可执行；
- 监控、日志、告警和回退开关可用；
- 失败结果能定位到构建、环境、数据或产品责任；
- 未执行范围和风险接受者已经记录。

### 发布证据

{% note primary flat %}
发布证据至少包含候选版本、构建与迁移结果、P1 用例、严重缺陷处置、未测范围、回退点和责任人。每个结论都指向可重做的日志、用例或快照；“冒烟通过”只能证明最小入口可用。
{% endnote %}

## 安装与升级

### 配置与历史数据

{% timeline 升级验证闭环, blue %}
<!-- timeline 基线 -->
备份合成数据，记录旧版本、配置、迁移版本和可回退点。
<!-- endtimeline -->
<!-- timeline 升级 -->
执行安装/迁移，检查启动、数据结构和关键读写。
<!-- endtimeline -->
<!-- timeline 中断 -->
在隔离环境模拟中断、重复执行或依赖失败，确认状态可恢复。
<!-- endtimeline -->
<!-- timeline 回退 -->
执行批准的回退流程，比较数据、配置和用户可见行为。
<!-- endtimeline -->
{% endtimeline %}

### 中断回退

{% note warning flat %}
回滚代码不一定能回滚数据：向前兼容迁移、已写入的新字段、外部消息和缓存可能仍然存在。回退验证必须先问数据不变量、迁移逆操作和外部副作用，不能只把版本号改回去。
{% endnote %}

## 发布策略

### 蓝绿与滚动

| 策略 | 暴露方式 | 适合的验证 |
| --- | --- | --- |
| 蓝绿 | 两套环境切换流量 | 切换、会话、数据一致性与回退 |
| 滚动 | 分批替换实例 | 版本混跑、兼容和容量 |
| 灰度 | 少量用户/区域先接收 | 指标、错误率、回退阈值 |
| 实验 | 按分组比较行为 | 统计口径、隔离和终止条件 |

{% note info flat %}
发布策略改变风险暴露顺序，不会自动减少测试责任。混合版本期间要验证接口和数据兼容；灰度要提前定义停止阈值；任何自动回退都必须有可观察指标和人工兜底。
{% endnote %}

### 灰度与实验

{% note info flat %}
灰度先定义分组、暴露范围、停止阈值和回退动作，再比较错误率、关键功能成功率与数据一致性。实验分组不能把权限或敏感数据泄露给不该看到的用户；指标异常时先保护用户和数据，再分析原因。
{% endnote %}

## 维护反馈

### 线上观察

{% note danger flat %}
线上反馈不是“用户自己测”。记录事件时间、版本、影响范围、脱敏请求 ID、指标和恢复动作；把可重复的行为转为回归候选，把一次性外部故障与产品缺陷分开分析。
{% endnote %}

### 问题复盘

| 复盘问题 | 需要留下的证据 | 后续改进 |
| --- | --- | --- |
| 为什么线上才发现 | 变更影响、未测范围和监控信号 | 补风险分析或发布检查 |
| 为什么回退不够快 | 时间线、依赖和数据状态 | 演练回退与告警 |
| 如何避免重复发生 | 根因假设、修复确认和回归结果 | 把稳定检查加入回归集 |

## 常见问题

{% flashcard basic id:testing-basics-a15-concept-1 deck:"测试基础" priority:2 tags:"修复确认,回归" %}
--- question
修复确认和回归测试有什么区别？
--- answer
修复确认重跑原失败条件，验证问题消失；回归测试检查变更影响的相关行为没有被破坏。
--- explanation
冻结账户仍可登录的修复确认只重跑冻结账户、正确密码和会话检查；回归还应覆盖正常登录、错误密码、解锁、权限和共享认证组件。回归范围由影响分析决定，不一定是全量，也不能只看页面提示。两者都要记录版本、数据和实际结果。
{% endflashcard %}

{% flashcard basic id:testing-basics-a15-concept-2 deck:"测试基础" priority:2 tags:"冒烟,准出" %}
--- question
冒烟测试通过能否直接发布？
--- answer
不能。冒烟只说明最小入口和依赖可用，发布还需满足高风险准出条件并处理严重缺陷、迁移、回退和剩余风险。
--- explanation
核心入口可打开并不代表支付超时、权限隔离或数据恢复正确。冒烟失败通常阻塞后续回归；冒烟通过后仍需按变更影响执行针对性回归，并给出未测范围和责任人。若业务明确把冒烟作为准入门槛，也不能把它升级成“没有缺陷”的保证。
{% endflashcard %}

{% flashcard basic id:testing-basics-a15-concept-3 deck:"测试基础" priority:2 tags:"回滚,数据迁移" %}
--- question
为什么回滚代码可能恢复不了数据？
--- answer
数据迁移、外部副作用、缓存和新旧版本写入可能不可逆；回滚必须验证数据不变量与兼容策略，而不只是切换代码版本。
--- explanation
新版本可能写入旧版本不认识的字段，消息已经发给外部系统，或迁移删除了旧数据。回退方案应包含备份/恢复、双写或兼容读取、缓存清理、未完成任务处理和恢复后核对。演练要在隔离环境进行，并记录可接受的数据损失和恢复时间。
{% endflashcard %}
