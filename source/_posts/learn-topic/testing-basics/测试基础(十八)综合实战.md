{% note info flat %}
本篇把前面的功能测试方法串成一个可交付练习：对教学图书借阅系统澄清需求、建立模型、写用例、执行并记录、提交缺陷、回归和汇报风险。所有规则、数据和结果均为合成示例，不伪造真实运行记录。
{% endnote %}

## 需求与范围

| 规则 ID | 教学约束 | 需要确认 |
| --- | --- | --- |
| LBR-01 | 启用会员可借可用图书 | 访客和冻结会员的入口行为 |
| LBR-02 | 单会员最多 3 本 | 按册数还是种类计算 |
| LBR-03 | 借阅后库存减 1 | 并发竞争和失败补偿 |
| LBR-04 | 归还后记录完成、库存加 1 | 重复归还与逾期费用 |

{% note primary flat %}
先把显式规则、教学假设和待澄清项分开，再冻结本轮范围：借阅、归还、资格、库存和核心错误恢复；真实支付、消息和大规模性能不在本练习中。范围决定证据能支持多大的结论。
{% endnote %}

## 测试设计

{% mermaid %}
flowchart TD
  R[需求与约束] --> E[输入域：会员/库存/数量]
  R --> D[判定表：资格与库存]
  R --> S[状态机：借阅/归还]
  E --> C[代表用例]
  D --> C
  S --> C
  C --> T[执行、证据与风险]
{% endmermaid %}

{% note primary flat %}
每条用例关联至少一个规则和覆盖项。等价类负责输入代表值，判定表负责条件组合，状态机负责合法/非法转换；方法互补，不要用一套模型替代所有问题。
{% endnote %}

| 用例 | 前置/数据 | 步骤 | 可判定预期 | 优先级 |
| --- | --- | --- | --- | ---: |
| LBR-01-01 | 启用会员 M，库存 1 | 借阅图书 B | 记录新增、库存 0、会员借阅数 +1 | 1 |
| LBR-01-02 | 冻结会员 M，库存 1 | 提交借阅 | 拒绝，无记录新增、库存不变 | 1 |
| LBR-02-01 | M 已借 3 本 | 再借可用 B | 拒绝并说明上限，库存不变 | 1 |
| LBR-03-01 | B 已借出 | 重复借阅 B | 拒绝无库存，不产生重复记录 | 1 |
| LBR-04-01 | 存在已完成借阅 | 再次归还同记录 | 拒绝或幂等，库存只增加一次 | 1 |

## 执行与记录

| 记录项 | 示例 | 用途 |
| --- | --- | --- |
| 版本/环境 | build-12、合成数据库、时区 UTC | 重现边界 |
| 数据 | member-M frozen、book-B stock=1 | 固定前置 |
| 动作 | 请求/页面步骤和时间 | 复现操作 |
| 实际结果 | 状态、响应、数据和日志 ID | 判断差异 |
| 清理 | 删除会话、恢复库存、保留最小快照 | 隔离后续用例 |

{% note warning flat %}
执行前的“预期”不是“实际结果”。只有真实运行并保存证据后，才能把一条用例标为通过或失败；本页的表格是练习模板，不声称已经连接某个借阅系统执行。
{% endnote %}

## 缺陷与回归

{% timeline 缺陷闭环, blue %}
<!-- timeline 复现 -->
在 build-12 用冻结会员和正确数据重现“借阅成功”。
<!-- endtimeline -->
<!-- timeline 记录 -->
提交预期/实际、步骤、会话和库存证据，标记影响与优先级。
<!-- endtimeline -->
<!-- timeline 修复确认 -->
在修复版本重跑原用例，确认冻结会员无会话、库存不变。
<!-- endtimeline -->
<!-- timeline 回归 -->
重跑正常会员、上限、无库存和归还相关用例，检查共享逻辑未被破坏。
<!-- endtimeline -->
{% endtimeline %}

{% note primary flat %}
回归范围由影响分析决定：资格检查修复至少影响正常/冻结/上限路径，库存写入修复还影响借阅、归还和并发不变量。关闭缺陷前保留版本、数据、实际结果和未覆盖风险。
{% endnote %}

## 报告与答辩

| 报告结论 | 支撑证据 | 限制与风险 |
| --- | --- | --- |
| 已执行的 P1 借阅规则符合预期 | 用例 ID、版本、结果和数据记录 | 未覆盖外部身份服务和大规模并发 |
| 冻结会员问题已修复并回归 | 原失败步骤、修复版本和关联用例 | 仍需关注其他入口的权限复用 |
| 可否发布 | 高风险结果、严重缺陷决定、回退能力 | 由业务责任人接受剩余风险 |

{% note success flat %}
答辩时先说范围和假设，再展示模型、代表用例、失败证据、回归范围和未覆盖项。不要把用例数量、通过率或“没有新缺陷”包装成整个系统正确的保证。
{% endnote %}
