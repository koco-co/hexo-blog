{% note info flat %}
本篇把前面的功能测试方法串成一个可交付练习：对教学图书借阅系统澄清需求、建立模型、写用例、执行并记录、提交缺陷、回归和汇报风险。所有规则、数据和结果均为合成示例，不伪造真实运行记录。
{% endnote %}

## 需求与范围

### 业务规格

| 规则 ID | 教学约束 | 需要确认 |
| --- | --- | --- |
| LBR-01 | 启用会员可借可用图书 | 访客和冻结会员的入口行为 |
| LBR-02 | 单会员最多 3 本 | 按册数还是种类计算 |
| LBR-03 | 借阅后库存减 1 | 并发竞争和失败补偿 |
| LBR-04 | 归还后记录完成、库存加 1 | 重复归还与逾期费用 |
| LBR-05 | 同一借阅请求 ID 重试只产生一次借阅副作用；已完成归还再次提交返回 `409 ALREADY_RETURNED` | 幂等响应体和审计记录 |
| LBR-06 | 写入失败必须回滚库存和借阅记录，不能留下半条成功数据 | 故障注入点和回滚日志 |
| LBR-07 | 最后一册并发竞争只能成功一次，库存不能为负 | 锁/事务证据与响应顺序 |

{% note primary flat %}
先把显式规则、教学假设和待澄清项分开，再冻结本轮范围：借阅、归还、资格、库存和核心错误恢复；真实支付、消息和大规模性能不在本练习中。范围决定证据能支持多大的结论。
{% endnote %}

### 验收约束

| 验收项 | 可判定条件 | 证据要求 |
| --- | --- | --- |
| 资格 | 启用会员可借；冻结会员不能新借但可归还已有记录 | 会员状态、借阅响应、前后快照 |
| 上限 | 当前未归还数达到 3 时拒绝新借；逾期标记仍计数 | 计数、拒绝原因、库存不变 |
| 库存 | 成功借阅减 1，归还加 1，失败不产生半条记录 | 库存、记录数、请求 ID |
| 幂等 | 同一请求重试、重复归还不重复产生副作用 | 幂等键、最终状态和审计记录 |

## 测试设计

### 模型与覆盖

{% mermaid %}
flowchart TD
  R[需求与约束] --> E[输入域 E1-E13：会员/库存/数量]
  R --> D[判定表 D1-D12：资格与库存]
  R --> S[状态机 S1-S3：借阅/归还]
  E --> C[代表用例]
  D --> C
  S --> C
  C --> T[执行、证据与风险]
{% endmermaid %}

{% note primary flat %}
每条用例关联至少一个规则和覆盖项。等价类负责输入代表值，判定表负责条件组合，状态机负责合法/非法转换；方法互补，不要用一套模型替代所有问题。
{% endnote %}

| 模型编号 | 本练习中的具体含义 |
| --- | --- |
| E1/E2/E3/E4 | 启用、冻结、达到 3 本、含逾期记录的会员输入域 |
| E5/E6/E7/E8/E9 | 库存为 0、最后一册、已完成记录、冻结但有记录、冻结完成态 |
| E10/E11/E12/E13 | 未知会员、未知图书、写入故障注入、最后一册并发 |
| D1/D2/D3/D4 | 资格允许、冻结拒绝、达到上限拒绝、逾期仍允许 |
| D5/D6/D7/D8 | 缺货拒绝、借阅幂等、合法归还、完成态归还拒绝 |
| D9/D10/D11/D12 | 未知主体/资源拒绝、原子回滚、并发互斥 |
| S1/S2/S3 | 可用→借出、借出→归还、借出→归还→再次借出 |

### 优先级

| 用例 | 前置/数据 | 步骤 | 可判定预期 | 优先级 |
| --- | --- | --- | --- | ---: |
| LBR-01-01 | 启用会员 M，库存 1 | 借阅图书 B | 记录新增、库存 0、会员借阅数 +1 | 1 |
| LBR-01-02 | 冻结会员 M，库存 1 | 提交借阅 | 拒绝，无记录新增、库存不变 | 1 |
| LBR-02-01 | M 已借 3 本 | 再借可用 B | 拒绝并说明上限，库存不变 | 1 |
| LBR-03-01 | B 已借出 | 重复借阅 B | 拒绝无库存，不产生重复记录 | 1 |
| LBR-04-01 | 存在已完成借阅 | 再次归还同记录 | 返回 `409 ALREADY_RETURNED`，库存只增加一次 | 1 |

{% note primary flat %}
为了让综合题可以自己执行，先冻结夹具：`M1` 启用且当前未归还数为 1；`M1-L` 是独立注册的启用会员且预置 3 条未归还记录；`M2-F` 冻结且未归还数为 0；`M2-R` 冻结但有一条自己的进行中借阅；`M3` 启用且有 2 条未归还记录，其中 1 条逾期；未知会员为 `M-404`。图书 `B1` 库存为 2，`B1-LAST` 库存为 1，`B2` 库存为 0，未知图书为 `B-404`。另准备写入失败注入点 `after_stock_decrement_before_record`，以及 T16 的两个启用会员 `M4`、`M5`。逾期标记仍计入“当前未归还数”，但逾期本身不额外拒绝；冻结会员可以归还自己已有的借阅。
{% endnote %}

| Case | 规则 ID | 覆盖项/模型边 | 前置夹具与步骤 | 唯一预期结果 | 重点不变量 |
| --- | --- | --- | --- | --- | --- |
| T01 | LBR-01、LBR-03 | E1 启用会员；D1 资格允许；S1 可用→借出 | `M1` 当前 1 条，`B1` 库存 2；发送 `req-T01` 借 1 册 | HTTP 201；库存 1、未归还数 2、新增 1 条记录 | 记录与库存同一事务变化 |
| T02 | LBR-01 | E2 冻结会员；D2 资格拒绝 | `M2-F`、`B1`；发送 `req-T02` | HTTP 403 `MEMBER_FROZEN`；库存、记录、计数均不变 | 冻结会员无借阅副作用 |
| T03 | LBR-02 | E3 上限边界；D3 达到 3 拒绝 | 将 `M1-L` 预置 3 条未归还记录，借 `B1` | HTTP 409 `LIMIT_REACHED`；库存和记录不变 | 上限按当前未归还册数计算 |
| T04 | LBR-02 | E4 逾期仍计数；D4 未达到 3 允许 | `M3` 有 2 条未归还记录（1 条逾期），`B1` 库存 2；发送 `req-T04` | HTTP 201；未归还数 3、库存 1、新增 1 条；不返回逾期拒绝 | 逾期不被静默当成额外资格条件 |
| T05 | LBR-03 | E5 库存 0；D5 缺货拒绝 | 固定代表会员 `M1` 借 `B2` | HTTP 409 `OUT_OF_STOCK`；库存仍 0、无新记录 | 缺货不可创建借阅 |
| T06 | LBR-03 | E6 最后一册边界；S1 借出 | `M1` 借 `B1-LAST`（库存 1），再用新请求重复借 | 第一次 HTTP 201 库存 0；第二次 HTTP 409 `OUT_OF_STOCK` | 库存不为负 |
| T07 | LBR-05 | D6 相同请求 ID 重试；S1 只迁移一次 | 对 `M1`/`B1` 连续提交两次完全相同的 `req-T07` | 两次均返回同一借阅结果；最终只新增 1 条记录、只扣 1 册 | 借阅副作用幂等 |
| T08 | LBR-04 | S2 借出→归还；D7 合法归还 | 预置 `M1` 的进行中记录 `R-T08`，库存 0；提交归还 | HTTP 200；`R-T08` 变完成、库存 1、未归还数减 1 | 归还守恒 |
| T09 | LBR-05 | E7 已完成终态；D8 重复归还 | 对已完成的 `R-T08` 再提交新请求 `req-T09` | HTTP 409 `ALREADY_RETURNED`；记录、库存、计数均不变 | 完成态不可重复副作用 |
| T10 | LBR-01、LBR-04 | E8 冻结但拥有记录；S2 合法归还 | `M2-R` 冻结且有自己的进行中 `R-T10`，库存 0；提交归还 | HTTP 200；记录完成、库存 1、会员仍为 frozen | 归还权限与借阅资格分离 |
| T11 | LBR-05 | E9 冻结会员完成态；D8 重复归还 | 对已完成的 `R-T10` 再提交归还 | HTTP 409 `ALREADY_RETURNED`；无任何新增变化 | 冻结会员归还同样幂等 |
| T12 | LBR-01 | E10 未知主体；D9 入口校验失败 | `M-404` 借 `B1` | HTTP 404 `MEMBER_NOT_FOUND`；所有状态不变 | 未知主体不可写数据 |
| T13 | LBR-03 | E11 未知资源；D10 资源校验失败 | `M1` 借 `B-404` | HTTP 404 `BOOK_NOT_FOUND`；会员计数、库存和记录不变 | 资源校验先于写入 |
| T14 | LBR-06 | E12 故障注入；D11 原子性回滚 | 在 `after_stock_decrement_before_record` 注入失败，提交 `req-T14` 借 `B1`；保存请求/日志 ID | HTTP 500 `INJECTED_WRITE_FAILURE`；库存恢复原值、无记录、计数不变；日志含回滚事件 | 失败不能留下半条数据 |
| T15 | LBR-03、LBR-04 | S3 借出→归还→再次借出；D1/D7 | 步骤 1 `M1` 借 `B1`；步骤 2 归还步骤 1 生成的记录；步骤 3 用新 ID 再借 `B1` | 步骤 1 后库存 1/计数 2；步骤 2 后库存 2/计数 1/记录完成；步骤 3 后库存 1/计数 2/新增 1 条 | 三步状态和库存变化可逐步追溯 |
| T16 | LBR-03、LBR-07 | E13 最后一册；D12 并发互斥；S1 | `B1-LAST` 库存 1，启用会员 `M4`、`M5` 各 0 条；两个请求在同一屏障后并发提交 `req-A`/`req-B`，记录锁/事务日志 | 恰好 1 个 HTTP 201、1 个 HTTP 409 `OUT_OF_STOCK`；最终库存 0、记录 1、无负库存；响应先后以时间戳为准，不假定请求先发者必胜 | 必须有并发请求时间、锁/事务和最终快照证据 |

{% note warning flat %}
执行时逐条保存“前置快照→步骤→实际响应→后置快照”。如果第 T04 或 T16 的实际行为与冻结规则不同，先提交缺陷或需求问题，再修改用例，不为了让表格全部绿色而改写预期。
{% endnote %}

## 执行与记录

### 环境与数据

| 记录项 | 示例 | 用途 |
| --- | --- | --- |
| 版本/环境 | build-12、合成数据库、时区 UTC | 重现边界 |
| 数据 | `M1`/`M2-F`/`M2-R`/`M3`、`B1`/`B1-LAST`/`B2` 及故障注入点 | 固定前置与边界 |
| 动作 | 请求/页面步骤和时间 | 复现操作 |
| 实际结果 | 状态、响应、数据和日志 ID | 判断差异 |
| 清理 | 删除会话、恢复库存、保留最小快照 | 隔离后续用例 |

{% note warning flat %}
执行前的“预期”不是“实际结果”。只有真实运行并保存证据后，才能把一条用例标为通过或失败；本页的表格是练习模板，不声称已经连接某个借阅系统执行。
{% endnote %}

### 结果与证据

| 结果记录 | 最小字段 | 不能替代的证据 |
| --- | --- | --- |
| 用例执行 | Case、版本、前置快照、步骤、实际结果、结论 | 不能只填“通过/失败” |
| 状态与库存 | 会员状态、当前未归还数、库存、记录状态 | 不能只看页面提示 |
| 失败与缺陷 | 请求 ID、日志位置、复现概率、影响和关联规则 | 不能凭截图推断根因 |

## 缺陷与回归

### 复现与修复

{% note info flat %}
下面的时间线是“待执行闭环模板”，不是已经发生的线上记录；练习者必须把实际构建、请求 ID、日志和结果回填后，才能把状态改为已复现、已修复或已回归。
{% endnote %}

{% timeline 缺陷闭环, blue %}
<!-- timeline 复现 -->
模板步骤：在 build-12 用冻结会员和正确数据尝试重现“借阅成功”，记录实际响应和前置快照。
<!-- endtimeline -->
<!-- timeline 记录 -->
模板步骤：提交预期/实际、步骤、会话和库存证据，标记影响与优先级。
<!-- endtimeline -->
<!-- timeline 修复确认 -->
模板步骤：在候选修复版本重跑原用例，确认冻结会员无会话、库存不变。
<!-- endtimeline -->
<!-- timeline 回归 -->
模板步骤：重跑正常会员、上限、无库存和归还相关用例，检查共享逻辑未被破坏。
<!-- endtimeline -->
{% endtimeline %}

{% note primary flat %}
回归范围由影响分析决定：资格检查修复至少影响正常/冻结/上限路径，库存写入修复还影响借阅、归还和并发不变量。关闭缺陷前保留版本、数据、实际结果和未覆盖风险。
{% endnote %}

### 变更影响

{% note primary flat %}
假设修复了“冻结会员可以新借”的缺陷，直接确认 T02，回归还要覆盖启用会员成功、达到上限、无库存、冻结会员归还和其他入口的资格检查。假设修复库存写入，则扩展到借阅、归还、重复请求和最后一册竞争；影响分析决定集合，不能只重跑原失败行。
{% endnote %}

| 回退演练 | 可执行内容 |
| --- | --- |
| 触发条件 | T14 仍出现半条数据、T16 出现两个成功或负库存，或 P1 缺陷在候选版本未通过原失败用例 |
| 步骤 | 停止候选版本推广；切回上一已知版本；恢复执行前的合成快照；依次重跑 T01、T08、T14、T16；保存版本、请求、锁/事务和状态快照 |
| 验证边界 | 只验证本练习夹具的库存、记录、计数和幂等不变量；不代表真实生产回退已获授权，也不替代备份恢复、通知和数据迁移演练 |

## 报告与答辩

### 风险与结论

| 报告结论 | 支撑证据 | 限制与风险 |
| --- | --- | --- |
| 若本轮执行的 P1 借阅规则均符合预期 | 用例 ID、版本、实际结果和数据记录 | 未覆盖外部身份服务和大规模并发 |
| 若冻结会员问题在修复版本回归通过 | 原失败步骤、修复版本和关联用例的实际证据 | 仍需关注其他入口的权限复用 |
| 是否具备发布条件 | 高风险结果、严重缺陷决定、回退演练证据 | 由业务责任人接受剩余风险 |

{% note success flat %}
答辩时先说范围和假设，再展示模型、代表用例、失败证据、回归范围和未覆盖项。不要把用例数量、通过率或“没有新缺陷”包装成整个系统正确的保证。
{% endnote %}

### 复盘改进

- 将实际发现的新状态、新边界或新错误码补回需求、模型和用例追踪；
- 把稳定、可判定且高风险的检查转为回归候选，把一次性探索疑问保留为待澄清项；
- 记录本轮未覆盖的外部身份服务、大规模并发、持久化故障和真实通知，并为每项指定后续负责人；
- 若规则、数据或接口发生变化，更新版本化夹具后重新评估优先级和准出结论。
